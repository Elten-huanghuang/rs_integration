# RS Integration 1.3.2 更新公告

发布日期：2026-08-11

本公告覆盖从 `1.3.1-fix` 到 `1.3.2` 的全部功能与行为改动。此次版本重点重构了复杂配方规划和 RS 特殊搜索，并补齐批量合成、仪式配方、机器绑定、材料统计及多项模组兼容问题。

## 配方规划与预览性能

- 配方预览改为请求前检查带库存的需求树，一个请求只选择纯规划器或 typed resolver，不再先后台穷举失败、再回到主线程重复规划。
- 需求树会按实际库存逐项扣减，库存已满足的分支直接剪除；标签输入按“存在一个可满足候选”处理，避免一个大标签污染整张依赖图。
- 配方目录在服务端启动或数据包重载阶段统一构建，玩家第一次打开配方树时不再承担完整目录冷启动成本。
- 优化需求树库存走查和 typed resolver 的材料供应匹配，减少大库存、重复材料和大量 NBT 变体下的扫描次数。
- 对白色羊毛与染色羊毛、混凝土粉末、木材等同族材料增加无净收益转换保护，阻止搜索在颜色或材料变体之间递归绕路；精确指定产物和确有数量收益的转换仍可使用。
- 可复用催化剂配方会自动获得候选优先级，不需要手工枚举每条配方 ID。CraftTweaker `.reuse()` 等明确标记会被识别，无法满足催化剂路径时仍可选择普通路径。
- 后台纯规划和主线程 typed 预览分别使用独立时间预算。超时会返回明确的本地化提示，不再长时间占用服务端主线程。
- typed 预览增加公平准入队列：每 tick 只放行有限请求，同一玩家只保留最新请求；队列满或等待过久时返回“规划器繁忙”。
- 最大可合成数量改为可行、不可行、未知三态。探测超时或目录不完整时显示“无法确定”，不会再把未知当成不可行而静默压低数量。
- 增加快照采集、纯搜索、typed resolver、需求树走查、预览队列和超时原因等性能指标，便于区分排队、搜索和主线程执行成本。

## 批量合成与材料守恒

- 原版工作台批量合成改为跨 tick 分片执行，并使用每条合成链与全服共享的双层预算；多名玩家同时合成时会轮转分配执行额度。
- 大型原版合成节点会自动进入分片路径，等待下一 tick 时保持正确的运行状态和进度，不会被误判为完成或卡死。
- 每次原版合成都使用本次实际输入单独调用配方组装和剩余物逻辑，修复动态 NBT 输出、容器返还、工具耐久及批量执行结果不一致。
- 材料需求现在区分消耗品、可返还材料和可复用催化剂。单个工匠锤、罪孽囚笼等工具或催化剂不会再随批次数量放大；会实际损耗的工具仍按真实消耗计算。
- 修复同一种中间产物被多个后续步骤共享时的重复计数。例如一个方块可分解出 9 个粉末时，两个各需 4 个粉末的步骤只会需求一个方块。
- 修复非严格 NBT 输入被错误固化为展示物品 NBT、同物品不同 NBT 供应被错误合并，以及配方输出与实际组装结果身份不一致的问题。
- 改进网络插入、回收与并发图执行的数量守恒，避免部分插入、材料返还或共享中间产物造成重复计入或错误退款。
- 小型同步合成完成后会显示明确提示，不再无反馈地直接结束。

## 配方树与 JEI 交互

- 配方树、卡片和顶部“总需求”统一使用服务端传输的真实输入角色与总需求，不再在客户端重复乘以批次数。
- 修复树状图中相同材料无法正确合并、可复用材料显示几十份，以及库存和中间产物抵扣不一致的问题。
- “无法获取”的材料卡片和材料名称文字都可以单独点击 `+` 加入 JEI 收藏；顶部总需求中的单个按钮也提升了交互层级，不会再被其他图层遮挡。
- 修复打开玩家物品栏或合成访问器页面时，配方转移快捷键占用 `F` 导致物品无法正常切换副手的问题。
- 改进格式化物品名称的缺失材料提示，例如 Apotheosis 永恒药水护符会正确填入效果名称，不再显示 `Format error: %s`。

## RS 与 JEI 搜索

- 重做 RS 网格中的 `#` tooltip、`$` 标签和 `@` 模组搜索缓存，普通名称搜索及 tooltip 拼音扩展保持可用。
- JEI 运行时就绪后便开始预热完整物品目录，不再等玩家第一次打开 RS 网格。
- 搜索结果会先显示已经确认的部分，再随后台准备持续补齐，避免冷缓存时输入后长时间完全没有反应。
- tooltip、标签和模组文本分开准备；纯字符串倒排索引在后台构建为不可变快照，完成后一次原子发布，不再在客户端 tick 中逐条修改大型 `BitSet`。
- 一次批量快照只发布一次索引版本，避免数千物品乘多个搜索模式造成连续版本失效和重复查询。
- 索引使用物品类型、注册名和 NBT 组成的稳定键，不依赖 RS 临时 UUID；网格重建后不会保留不断增长的废弃 ordinal。
- 候选集合接近全部物品时自动改用分片扫描，避免倒排索引求交和复制本身比直接扫描更慢。
- 支持从磁盘复用 tooltip 与拼音文本；缓存未命中的条目会继续在后台补全。JEI 当前结果可作为首批显示，但最终结果仍由 RSI 完整扫描校验。
- 修复切换存档、重开网格或 RS 刷新列表时瞬时 `空列表 -> 完整列表` 导致索引被清空重建的问题。默认在 250ms 稳定窗口内保留上一份非空快照，真实空网格仍会正常清空。
- 修复“预热完成”日志早于候选索引实际完成的问题，并增加候选规模、索引发布、首批结果、空快照抑制和动态刷新指标。
- Sol Carrot 的“尝过/未尝过”状态在 RS 与 JEI 中按当前玩家正确显示，不会写入共享静态 tooltip 缓存，也不会把两个状态错误合并。
- SlashBlade 密集列表轻量渲染仍属于实验功能，本版默认关闭且不注册对应 Mixin；搜索优化不会改变拔刀剑物品的正常渲染。

## 特殊配方与模组兼容

- Nameless Trinkets / Apotheosis 护符材料改用语义 NBT 匹配：实际背包或 RS 网络中的药水护符可以作为递归材料，同时仍保留必要的药水效果身份。
- Wizards Reborn 水晶灌注不再对无声明要求的皇冠强制精确 NBT；普通装备状态和无关运行时数据不会阻止配方识别。
- SlashBlade 锻造配方兼容动态刀 NBT 与实际组装输出，并修复已知的空 `rodai` 配方覆盖数据。
- Goety 召唤、献祭和转化仪式改为安全的手动确认流程：RSI 只摆放基座材料，并把核心激活物交给玩家，不再自动启动可能吞材料或选错目标的仪式；此类仪式限制为单次准备。
- Goety 黑暗祭坛与亡灵火盆使用独立绑定规则，避免不同机器类型互相误匹配；研究、献祭和仪式类型检查也会在消耗材料前完成。
- Farmer's Respite 茶壶支持真实容器槽、非水液体、瓶装饮品和输出回收语义；已有不匹配液体时会保留原液并明确报错。
- Youkai's Homecoming 蒸笼结构支持一层蒸笼加盖子的紧凑结构，同时继续校验开放结构必须存在有效盖子。
- 修复 CraftTweaker、Malum、Embers 等配方中的催化剂识别、候选排序和剩余物语义，避免把可复用材料当批量消耗品，也不会把真实消耗的工具误判为免费催化剂。
- 修复共鸣存储物品的可见性与变体身份边界，避免外部 RS 视图或回收路径读到不应暴露的内部物品。

## 范围机器绑定

- 新增“绑定附近机器”快捷键，默认按键为分号 `;`。无线连接器可以放在饰品栏中使用，无需为了绑定临时取下。
- 扫描只访问已加载区块，并按服务端每 tick 时间预算分片执行；默认水平半径 24 格、上下各 12 格，扫描过程不会一次性阻塞服务器。
- 已绑定机器会跳过，不会重复写入；连接器被更换、无有效网络、同时装备多个连接器或扫描正在进行时会给出明确提示。
- 接入领地权限检查：不属于玩家且无交互权限的 FTB 圈地机器不会绑定。
- 完成提示会分别报告发现、成功绑定、已绑定跳过、权限跳过和无效结构数量。

## 背包、喂食与其他修复

- 修复 Sophisticated Backpacks 的 RS 喂食升级设置页、已绑定网络访问及补货/喂食插入记录，避免部分接受时数量统计错误。
- 自动进食会正确识别 Gnaw's Gift 等允许满饱食进食的效果，同时保留普通食物的饥饿度限制。
- 修复 Machine Hub 配方绑定与控制交互中的错误候选和无效机器类型。
- 多处面向玩家的失败原因改用可本地化组件，专用服务器不会再把原始翻译 key 或格式占位符直接发给客户端。

## 新增配置

以下配置会自动写入对应配置文件，旧配置会保留并按 schema 迁移：

- 规划路由与保护：`craftingPureDemandMaxNodes`、`craftingPurePlanningTimeoutMs`、`craftingTypedPreviewTimeoutMs`、`enableCraftingVariantConversionGuard`
- typed 预览队列：`craftingTypedPreviewQueueCapacity`、`craftingTypedPreviewAdmissionsPerTick`、`craftingTypedPreviewQueueTimeoutMs`
- 原版批量合成：`craftingVanillaOperationsPerTick`、`craftingGlobalVanillaOperationsPerTick`
- 催化剂候选：`enableCatalystRecipePreference`、`catalystRecipePreferenceBonus`
- 范围绑定：`nearbyBindingHorizontalRadius`、`nearbyBindingVerticalRadius`、`nearbyBindingMaxMachines`、`nearbyBindingTickBudgetMicros`、`nearbyBindingCooldownMs`
- 搜索调度：`gridSearch.idleBudgetMicros`、`activeBudgetMicros`、`debounceMs`、`partialRefreshMs`、`queryCacheEntries`
- 搜索索引：`gridSearch.candidateIndexMaxPercent`、`candidateRebuildDelayMs`、`emptySnapshotGraceMs`、`pinyinWorkers`
- 搜索磁盘缓存：`gridSearch.diskCacheEnabled`、`diskCacheEntries`、`diskCacheMaxMiB`、`diskCacheSaveDelayMs`
- 实验渲染：`gridSearch.lightweightSlashBladeRendering`，默认关闭，本版不注册对应实验 Mixin

## 兼容性说明

- 配方预览数据结构已经更新，统一网络协议由 29 升至 30。客户端与服务端必须同时更新到 `1.3.2`，旧版本会在连接阶段明确拒绝，不会带着不兼容数据包继续运行。
- 更新不会清除现有 RS 网络、机器绑定或搜索磁盘缓存。
- 本次没有进行规划器阶段 4-9 的全量领域模型重写；当前实现是在保留现有 `RecipeIndex`、typed resolver、Handler 和网络协议职责边界的前提下，增加路由、剪枝、预算和公平调度。

## 建议验证

1. 进入世界后搜索 `#zuz`、`#诅咒`、`$forge` 和常用 `@模组名`，确认结果会快速出现并持续补齐。
2. 多次关闭并重新打开 RS 网格、切换存档，确认搜索结果不会先清空再突然出现。
3. 预览复杂仪式、染色/木材转换和含催化剂的批量配方，确认规划时间、材料数量和执行结果正确。
4. 使用 `;` 扫描附近机器，确认已绑定机器和无权限领地会被跳过，并检查完成统计。
5. 多名玩家同时提交复杂预览与大型原版批量合成，确认请求会公平排队且不会由单次操作引发长时间服务器停顿。
