# RS Integration 1.5.2 更新公告

- 更新日期：2026 年 10 月 20 日
- 适用环境：Minecraft 1.20.1 / Forge 47+
- 上一版本：1.5.1

本次是 1.5.1 之后的一次大型功能更新，新增完整的魔法资源存取与递归合成链路、共振魔力池与共振魔源罐、多套料理机器兼容、服务端权威机器绑定索引和磁盘操纵器分片搬运，并集中修复了存储、终端、机器、批量执行与开发环境问题。以下内容仅涵盖 1.5.1 之后的变化，不再重复 1.5.1 已发布内容。

## 魔法资源统一存取

- 万界归墟盘新增 `MANA`、`SOURCE`、`SOUL` 三类魔法资源存储。三类资源独立计量、独立容量，不会与物品或流体互相换算。
- 混合终端新增随已安装模组启用的魔法资源分类，可查看储量与容量，并参与搜索、筛选和资源条目同步。
- 可在终端中使用带量容器直接充放魔法资源：Botania 魔力石板或魔力饰品、Ars Nouveau 魔源罐、Goety 灵魂图腾都会按容器实际余额与剩余空间转移。
- 手持 `ars_nouveau:creative_source_jar` 或 `botania:creative_pool` 在混合终端的魔法资源条目上右键，可一次充入配置数量，默认 `2100000000`；创造容器不会被消耗，RS 与 BD 都只接收实际可用容量。数量由 `magicResources.creativeMagicDepositAmount` 控制。
- 存取流程增加容量预检查和失败回滚。库存收不下时不会先清空容器；容器只写入一部分时，差额会退回库存，尽量避免资源丢失或重复。
- 新增魔法资源路由层。资源由当前终端所连接的 RS 归墟盘或 BD 网络决定权威来源，不会把 RS 与 BD 的余额自动相加。
- 服务端新增 `magicResources.pinnedBackend`。该选项只会在链路没有明确空间管辖时用于指定兜底后端，不会覆盖当前终端所属网络。
- 合成计划会携带并展示魔法资源费用，包括总需求、库存可用量和预计缺口。不可达资源不会再静默显示为 0。
- `/rsi_debug` 新增魔法资源路由与性能诊断段，可查看后端判定、预留账本和路由计数。

## Goety 灵魂资源链路

- 接入黑暗祭坛、诅咒之笼、灵魂烛台及 Goety 原生灵魂增减回调，网络灵魂资源可参与远程仪式与递归合成。
- 灵魂消耗由统一预留账本管理，支持 RS 归墟盘、BD 网络与机器或灵魂方舟共同补足，并记录实际提取和未完成预留。
- 灵魂方舟发生灵魂消耗时，可按剩余容量从绑定的 RS 网络反向补满。该功能由 `integrations.enableGoetySoulReverseRefill` 控制，默认关闭，同一玩家每 20 tick 最多尝试一次。
- 新增亡灵火炉虚拟灵魂烛台支持。递归合成没有实体烛台时，可使用 `integrations.goetyBrazierVirtualCandleCount` 指定数量的内存烛台推进进度，默认 64；每个烛台每 tick 消耗 1 点灵魂，配方总成本不变。
- 手动点火仍遵循 Goety 原版结构要求，虚拟烛台只影响 RSI 递归合成。
- 修复 Goety 火炉虚拟灵魂源与 Malum 材料槽映射，避免灵魂供能与材料写入落到错误槽位。

## 共振魔法容器

- 新增共振魔力池：以 Botania 原生 `ManaPoolBlockEntity` 为基础，保留魔力池的手动灌注、火花、接收器、输出模式与液面渲染。
- 新增共振魔源罐：以 Ars Nouveau 原生 `SourceJarTile` 为基础，支持中继器、分流器和原版魔源消费者直接传输。
- 共振魔力池与共振魔源罐均可绑定 RS 网络，并提供绑定提示、储量 HUD、客户端同步和持久化。
- 共振容器可接收第三方魔力与魔源输出，不需要为每个产能设备单独编写配方兼容。
- 修复 Ars Nouveau 魔源产出、原生输出、中继器和分流器无法正确接入共振魔源罐的问题。
- 修复 Botania 魔力石板等带量物品无法把魔力灌入万界归墟盘的问题。
- 新增升级配方：
  - 共振魔力池：魔力池四周放置 4 个石英富集铁。
  - 共振魔源罐：魔源罐四周放置 4 个石英富集铁。

## 料理机器扩展

- 支持 Twilight Delight 炽铁锅批量烹饪，并遵循原模组热源判定与 Farmer's Delight 烹饪规则。
- 支持 BOSSes' Delight 灵魂锅，可远程绑定、递归合成和批量投料，并校验灵魂锅下方的冰、浮冰或蓝冰冷源。
- 支持 Casualness Delight 炸锅，保留原生热源规则、容器返还和批量处理，并正确捕获由世界交互产生的成品。
- 支持 Farm & Charm 烹饪锅与烘焙机，并复用同一套原生热源、容器和批量规则扩展 Candlelight 汤锅及 Bakery 小烹饪锅。
- 完善 Youkai's Homecoming 烹饪锅与蒸笼的批处理配置、原料预载、容器返还及多机器执行。
- Farm & Charm 系列料理界面增加原生配方书合成按钮，可直接按当前配方发起 RSI 合成。
- 修复料理锅批量任务启动失败、炸锅结果读取失败、无进展任务未正确结束等问题。
- 补充料理机器相关提示的中英文翻译和失败原因显示。

## 磁盘操纵器与存储

- 磁盘操纵器新增高速分片搬运。所有磁盘操纵器共享单 tick 时间预算，可跨 tick 保存搬运游标，不再局限于原版一次仅处理少量资源的节奏。
- 支持物品与流体按资源类型批量搬运，并在网络或磁盘无法继续接收时进入无进展冷却，避免每 tick 重复扫描。
- 新增 `storage.diskManipulator` 配置组：
  - `enabled`：默认开启，关闭后完全恢复 RS 原版逻辑。
  - `budgetMicros`：所有操纵器共享的时间预算，默认 1000 微秒。
  - `maxOperationsPerTick`：单台操纵器每 tick 最大操作次数，默认 1024。
  - `maxItemsPerOperation`：单次操作最大资源数量，默认不设实际上限。
  - `noProgressCooldownTicks`：无进展冷却，默认 20 tick。
- 万界归墟盘持久化格式扩展为物品、流体、魔力、魔源和灵魂资源，并保留旧盘数据兼容。
- 加载检查点时会自动合并重复资源身份、修复重复记录，并以原子方式写回，避免数量被拆成多行或重复累计。
- 魔法资源库存、网络汇总、预留/退款、任务账本、计划费用、终端条目和 BD 路由统一使用 `long`；旧版魔法存档和旧任务账本继续按原 `int` 记录读取。
- Botania、Ars Nouveau、Goety 和 RS 仍使用 `int` 的原生接口只在边界显式饱和或分批，不会静默截断高位。
- 归墟盘的单个物品 Key 和流体 Key 也支持 `long`；旧数量页继续兼容，RS 原生缓存不足的部分由混合终端和规划快照统一补值，长提取请求按 `int` 分片执行。
- 修复磁盘仓重新联网后统一盘物品与流体视图未重建、存储缓存未刷新的问题。
- 网格搜索缓存迁移至 `rs_integration/cache/grid_search`，不再写入配置目录；旧 `config/rs_integration/grid_search_cache` 文件会在读取时自动迁移。

## 合成计划与终端

- 合成计划现在会在递归节点中携带魔法资源费用，并在计划图、缺料提示和执行阶段使用同一套口径。
- 关闭正在计算的计划界面后，结果会转为后台任务继续处理；完成后在聊天栏提示，并可点击“打开计划”恢复查看。
- 后台结果设有数量与时效限制，登出服务器时会自动清理，避免跨存档残留。
- 修复 RS 样板终端被 RSI 虚拟混合界面拦截的问题；样板终端继续使用原生行为。
- 精妙背包次元磁铁批量入库时，终端通知会合并显示，避免一次搬运刷出大量重复消息。
- 修复混合终端与递归合成的水瓶纯度兼容，带药水 NBT 的水瓶不会再被当作普通水瓶参与配方。
- 修复水瓶、药水及部分容器流体在装液、倒液和库存匹配中的纯度识别。
- JEI 原生铁砧配方现在可以通过加号直接切换到 RSI 铁砧界面，并正确携带两格输入，而不是落入普通工作台转移逻辑。

## 递归合成与批量执行

- 统一即时逻辑配方契约，覆盖原版工作台、流体容器转换、SlashBlade 工作台、Lychee 物品浸泡、Immortalers' Delight 温泉、Malum 虚空恩惠和 Farming for Blockheads 市场兑换。
- 纯兑换、逻辑转换和即时工作台配方使用统一批量委托，可安全按长数量缩放，并把超过单组堆叠上限的产物拆成多个受控结果片段。
- 可复用催化剂、容器和工具不会随执行次数被错误倍增；消耗材料、耐久与燃料则按实际执行规模计入预留。
- 批量调度改为稳定的逻辑批次，不再把每一步都当作独立操作消耗预算。大量工作台物品、压缩方块和纯兑换可以在单个执行窗口内快速完成。
- 实体机器会根据输入缓存、输出空间、可复用材料数量、并行能力和安全上限计算实际 batch，而不是盲目扩到最大数量。
- 同一物理机器在并行窗口内只能被一个 worker 占用；所有候选机器均被租约占用时，后续任务会等待而不是重复启动。
- 修复即时机器批量倍率、EAEP 式自动合并拆分、工作台并行和多方块机器委托之间的语义不一致。
- 合成计划协议支持超过 `Integer.MAX_VALUE` 的长数量与分页传输，修复大配方图截断、重复数量绘制和分页重组问题。
- 修复配方分支选择可能泄漏到下一次计划、计划租约被旧缓存重放、以及纯规划与 typed 规划回退重复计算的问题。
- 优化大型配方图的后台规划、输入快照缓存、进度增量上报、内存节点限制和切换性能；慢索引与超预算阶段会输出可定位的诊断信息。
- 后台规划完成提示不再在进入后台时立刻刷聊天栏，只在计划真正完成后提供可点击的恢复入口。

## 燃料、耐久与退款

- 统一材料消费语义，明确区分一次性消耗、按执行次数缩放、可复用催化剂、工具耐久和机器燃料。
- 修复耐久工具在大量重复执行中被重复预留、燃料被按错误单位缩放，以及可复用工具被错误当作消耗品的问题。
- 修正 Aether 冷冻器冰石燃料、Enchantal Cooler、料理锅燃料和多类机器燃料的读取与预留口径。
- Farmers' Delight 刀具、Malum 聚焦材料、CrockPot 燃料等特殊输入现在会使用与原生机器一致的实际消耗规则。
- 离线合成产生的普通物品退款会写入世界存档，玩家登录时自动领取；背包已满时保留在退款队列中，可通过 `/rsi_item_refund` 补领。
- 跨 RS、BD 与玩家背包的材料预留增加来源隔离和回滚测试，失败时只返还本轮实际提取的片段。

## 机器中心与绑定索引

- 终端侧边机器按钮和 `P` 管理入口统一为机器中心。存在合成任务时优先打开任务页，并可切换到全部绑定机器。
- 绑定条目迁移到服务端权威索引，终端物品 NBT 只保留稳定 book UUID；旧版 `aec_bindings` 数据会在登录或首次访问时自动迁移并清理。
- 每个绑定机器拥有稳定的 `MachineEndpointId`，更新显示名、方块身份或终端副本时不会改变端点身份，为后续任务恢复和崩溃恢复提供基础。
- 机器索引按终端书、坐标、玩家所有权和端点评分版本建立缓存。异步合成线程只读取不可变快照，不在工作线程解析物品 NBT。
- 绑定同步改为 128 条一块传输，并按玩家端点评分指纹跳过未变化的完整快照，避免物品侧栏每次刷新都重复发送全部机器。
- “全部绑定机器”界面改为信息卡片网格，显示机器名、维度、`X/Y/Z` 坐标、收藏、解绑和已拉黑状态；无 GUI 机器也会出现在管理页。
- 自动化黑名单现在同时作用于终端标签、Hub、收藏栏、侧栏 GUI 图标、JEI/EMI 递归合成按钮、计划候选和执行候选，不再出现入口可用但启动阶段才拒绝的情况。
- 黑名单机器仍保留在 P 管理页中方便恢复。右键单击可切换单台状态，按住右键拖动可框选批量拉黑；选区内全部已拉黑时再次框选会统一恢复。
- 黑名单变化会立即刷新机器入口并失效服务端扫描、计划快照与配方兼容缓存。
- 并行容量只计算未被拉黑的机器。两台同类机器拉黑一台后，只会分配一个 worker，不会重复占用剩余机器。
- JEI 与 EMI 的机器按钮现在同时检查黑名单和具体机器的配方兼容性，不再仅凭“同模组存在任意绑定”就显示递归合成按钮。
- 修复直接终端计划在材料足够时绕过物理机器绑定检查的问题。现在必须先存在可执行且未拉黑的匹配机器，才允许进入物理合成链。

- 补充语言键一致性检查和多项回归测试，降低中英文缺失与可选依赖加载错误。

## 开发者 API

- 新增 RS 魔法资源公开入口 `RsiMagicApi`，可按服务端或指定 RS 网络查询 `amount`、`available`、`insert`、`extract` 和 `reserve`。
- 新增 BD 魔法资源公开入口 `BdMagicApi`，提供 `MANA_KEY`、`SOURCE_KEY`、`SOUL_KEY` 及对应网络的读取、插入和提取。
- `BdMagicApi.registerAlias(alias, canonical)` 可把第三方注册的等价 Key 规范到同一库存行，减少不同模组重复创建语义相同的资源。
- RS API 只访问 RSI 归墟盘账本，BD API 只访问获授权的指定 BD 网络；两边不会隐式共享或合并库存。
- 魔法资源保留 `MagicResourceKind` 的可用性与递归合成能力声明，第三方可在调用前判断当前安装组合是否支持对应资源。

## 升级说明

- 本次涉及归墟盘数据格式扩展、重复记录修复和磁盘操纵器行为变更，升级前请备份世界。
- 首次加载会创建 `rsi_machine_bindings.dat`，并把旧终端中的绑定列表迁移到服务端索引。升级后请保留一次完整世界备份。
- 多人游戏请同步更新客户端与服务端，并使用相同的 RSI 版本。
- 首次启动会生成新的 `storage.diskManipulator`、`magicResources.pinnedBackend` 和相关 Goety 配置项；已有配置通常会保留。
- 新增的魔法资源只有在对应 Botania、Ars Nouveau 或 Goety 已安装且兼容开关启用时才会出现在终端中。
- 若服务器更重视 tick 稳定性，可先降低 `budgetMicros` 或 `maxOperationsPerTick`；若外部存储较慢，可调低 `maxItemsPerOperation`。
- 发布文件名：`rs_integration-1.5.2.jar`。
