# RS Integration 1.6.1 更新公告

公告日期：2026 年 11 月 18 日
适用环境：Minecraft 1.20.1 / Forge 47+
对比版本：1.6.0.1

1.6.1 重点改善复杂合成计划的生成、材料显示和执行确认。缺料时可以查看计划，补齐后先重算、再确认；规划超时时，也能查看已经计算出的部分。

## 材料与执行确认

- 修复材料表和悬浮提示把未确认来源的原料误标成「已安排补做」的问题。库存、缺口和未确认来源分开显示。
- 补料后重算会读取当前库存，不复用旧的失败预览。新结果会先在原页面显示，只有再次点「确认执行」才会下单。补料、重算和等待回包都不会自动执行。
- 对缺料旧预览的执行请求，服务端会明确提示重新规划，不再统一报「计划已失效或状态变动」。实际下单仍会复验材料、存储网络和机器状态。

## 大型规划与执行

- 减少深层、宽分支和多模组配方的重复搜索与回溯，并分批处理部分服务端检查和机器估算，减轻生成计划时的卡顿。
- 规划超时会保留只读配方树和已结算材料。草稿不是完整订单，不能执行；未算到的材料也不会按零缺口处理。
- 统一递归任务的依赖调度。执行中需要补料时，规划可跨 tick 继续，并按当前任务剩余需求核对补料数量。

## 兼容性与诊断

- 改善烹饪锅动态配料、多层蒸笼自动合成、嬗变台连续嬗变和刷怪笼升级预览。
- 改善无存储网络时的工作台催化剂规划，统一空 NBT 与无标签物品的运行时匹配。
- 汇总配方目录采集的同类超时告警，保留次数与最慢项，减少日志刷屏。
- 增加计划界面注释、合成成功事件与缺货取物回退接口，详见 [开发者 API 文档](../api/README.md)。

## 升级与测试

- 使用本次发放的 1.6.1 群测包替换旧版 RSI，不要同时保留两个版本。联机时客户端和服务端都要使用同一个构建。
- 打包和相关离线回归已通过。本轮尤其需要整合包实测缺料补齐后的重算、复杂计划的完整性，以及多人或管道持续入库时的表现。
- 建议先试糖浆的「缺料 → 补齐 → 重算 → 确认」，再试创造之心一类的大型多模组合成。反馈请附整合包版本、目标配方 ID、操作步骤、截图和对应时间的 `latest.log`。
