# RS Integration 1.5.2.2 更新公告

- 更新日期：2026 年 10 月 28 日
- 适用环境：Minecraft 1.20.1 / Forge 47+
- 上一版本：1.5.2.1
- 公告范围：只列 1.5.2.1 之后的变化；1.5.2.1 及更早的内容见对应公告，不再重复。

本次小修版集中在四条线上：无处理时间的配方合成太慢、部分配方被误判成"没有已绑定机器"、批量执行卡住时不给原因、万界归墟盘在区块重载后不自动恢复。

## 合成速度与批量

- 切石机、锻造台这类没有处理时间的机器配方，现在一次派发就能完成整批操作（单次最多 64 次），不再一次只推一个操作、每 tick 都等一轮结果。
- 批量仍按真实材料和产出结算：材料不足时会自动缩到能做的数量；一份产物超过一组时拆成多个物品堆，不会丢产物，也不会按整批重复结算。
- 熔炉、高炉、烟熏炉、营火这类真的有处理时间的机器不受影响，继续按每 tick 的可执行操作数推进。
- 砧板这类带工具的配方，不可损坏的工具按"可反复使用"计算，批量合成不再要求一次准备 N 把刀。
- 生物炼金台一批扣多次营养，启动前按次数累计备料，并按燃料槽容量收紧单批次数，避免中途营养耗尽把结果槽清空。
- 计划界面显示的次数、实际提交的材料和最终产物保持同一口径；中途取消只回收没用掉的预留材料。

## 配方与绑定判定

- 高炉、烟熏炉、切石机的配方不再被当成熔炉去查绑定，切石与烧炼不用再为了报"没有可用的已绑定机器"绕路。
- 模组级兜底机器类型（本身没有可绑定方块）下的普通合成配方，不再因为查不到绑定被拒。
- 农夫乐事面团这类"在工作台里手工装配"的特殊配方，按通用逻辑合成执行，不再要求绑定机器；材料按配方自身规则声明（例如 1 小麦 + 1 水桶，水桶按剩余物返还）。
- 特殊配方没有材料数据时给出明确诊断，不再把零材料当成可执行配方放行。
- 递归图放行改成统一判定：产物全部确定的砧板配方（例如玉米粒这类中间产物）可以正常参与递归规划；带概率产物的配方只作为目标节点使用，不会因为"可能产出"被当成必然中间产物。
- 概率产物不再被当成必需次产物结算，主产物本身带概率时改走定向重试，不再出现"产物缺失"的假失败。

## 执行稳定性与诊断

- 图节点长时间（600 tick，约 30 秒）停留在同一等待原因时中止并写明原因，不再整条链永久停在"准备中"。
- 绑定查询增加从粗类型到具体类型的回退，并输出逐层过滤诊断（哪些绑定因为类型、子类型、兼容性或禁用被排除）。
- 生物熔炉启动失败会带上具体原因，故障报告不再只有兜底文案。
- 发酵桶启动被拒时补日志，不再无声退出。
- 客户端对同一条失败提示做 3 秒去重，避免预览重算把聊天栏刷满。

## 存储与递归合成

- 万界归墟盘所在区块被卸载后重新加载时，会自动重新挂载物品与流体视图，不再出现"盘还在驱动器里、终端却是空的"，也不需要手动拔插刷新。
- 节点或方块实体只是短暂不可用时会保留待恢复记录，恢复后自动重建库存视图；只有确认盘被拿走或驱动器被换成别的方块节点时才放弃恢复。
- 长时间（约 2 分钟）等不到方块实体恢复的记录会被清理，避免残留条目长期占用槽位。
- 区块恢复期间不会同步加载区块，也不会在服务器线程里反复刷新盘位缓存。

## 终端与界面

- 铁砧命名改用原版输入框，支持输入法、粘贴和光标编辑，中文与表情符号名称按 UTF-8 字节数截断，不再因为字符数没超而写入失败。

## 升级提醒

- 多人游戏请同步更新客户端与服务端，使用相同版本的 RSI。
- 已有的配置、存档、机器绑定和万界归墟盘内容继续兼容，不需要手动迁移。
- 之前因为"没有可用的已绑定机器"而绕路使用其他配方的存档，升级后可以直接用切石机、高炉等机器合成。
- 发布文件名：`rs_integration-1.5.2.2.jar`。
