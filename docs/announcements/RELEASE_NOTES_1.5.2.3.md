# RS Integration 1.5.2.3 更新公告

- 更新日期：2026 年 10 月 29 日
- 适用环境：Minecraft 1.20.1 / Forge 47+
- 上一版本：1.5.2.2
- 公告范围：只列 1.5.2.2 之后的变化；1.5.2.2 及更早的内容见对应公告，不再重复。

本次更新集中处理并行调度的“默认行为”和递归计划的展示：普通机器不再需要手写并行声明，熔炉类按真实并行机器计算燃料，催化剂和耐久工具按“每台机器一份”取上限，递归树里能直接看到每台机器的份额。同时修复了祭坛、Embers、砧板、农夫乐事锅和污染大地之心在实际游戏中的一批执行问题。

## 并行调度

- 取消 `craftingOperationsPerDispatch`、`craftingMaxConcurrentGraphNodes`、`craftingGraphDispatchPerTick`、`craftingGraphDispatchPerCraft`、`craftingMaxConcurrentOperations`、`craftingOperationDispatchPerCraft` 这些并行/派发硬限制，调度器按当前操作数、可用机器和材料动态推进。
- 取消 `craftingParallelDisabledMods`、`craftingParallelDelegatePolicies`：不再需要用配置手动关掉某个模组或 delegate 的并行。
- 普通机器默认具备并行能力，由 delegate 的 `concurrencyCapabilities()` 统一声明；不再依赖 `GraphConcurrencyEligibility` 的少量白名单，也不再要求机器主动声明后才能并行。
- 并发能力改为按“材料是否链式预留、输出归属、清理方式、副作用、准备契约、支撑位置”判断；未知契约、模糊输出、延迟清理、非本地副作用会自动退回独占，保证不会为了并行牺牲正确性。
- 并行组按机器数均衡分配操作：3 个操作、2 台机器会分成 `2 + 1`，第一轮就把每台机器的份额发出去，不再让 worker 反复抢 `ceil(剩余/worker)` 的批。
- 图执行不再因为全局操作预算暂时为 0 而无限重试；拿不到并行预算时会直接退回顺序执行。等待超过 6 秒没有任何进展时自动失败并给出原因，不会永久停在“准备中”。
- 修复同一条链在“多机器并行”和“单机器批处理”之间反复切换时释放/重新获取 delegate 导致的自锁；组内准备失败会保留具体 detail，而不是只报“无法准备 worker”。

## 递归计划与界面

- 计划树新增并行信息：显示参与并行的机器台数、每台机器的操作份额，以及燃料、催化剂、耐久工具的实际消耗。
- 熔炉类燃料改为按每个 worker 的真实操作数计算：每个并行机器单独补自己的燃料，计划里显示的是所有 worker 的燃料总和，而不是“只按一批算一份”。
- 催化剂按 `min(现有催化剂数量, 可并行机器数)` 取并行 worker 数；一份催化剂可以被同一 worker 的整批操作复用，但不会被多台 worker 共用。
- 带耐久工具的配方（砧板、切割类）同样按“每台 worker 一份工具”计算，计划里显示工具消耗，不再只显示一份。
- 预先按单变体可行性估算机器批处理：tag 输入（例如 `youkaishomecoming:dango`）在计划阶段就会按“同一变体填满一个槽位”检查，不再出现“预览说能做、执行说缺料”。
- 缺料诊断按 tag 聚合：同一槽位的多个变体失败时，主提示给出 tag 级需求和数量，具体每个变体的深层材料放进诊断，不再把多套变体的缺料并集成一长串无关材料。
- JEI 递归树、计划树、计划图都会显示“机器槽位要求同一种变体”的提示；带容器的机器配方会显示容器需求。
- 修复单层配方（没有递归图节点）时计划树不显示并行/燃料/催化剂的问题；计划响应和网络包同步了新的并行字段，客户端与服务端版本需要一致。

## 机器兼容与执行

- Malum 精魂祭坛：只使用玩家手动绑定的祭坛，不再自动扫描相邻方块；四台已绑定的祭坛可以并行。底座空间不足、精魂槽不足等提示改为中文诊断/计划警告，不再反复刷聊天栏。
- Embers 炼金：固定配方和已经猜出代码的配方允许并行；只有真正未知、仍在推断的配方保持独占。已经缓存代码的配方不会再被 `GraphConcurrencyEligibility` 误判成“世界捕获”。
- Aetherworks 铁砧：不再针对 `goety:dark_wand` 做易变 NBT 特判；提取账本改为通用兜底（精确身份 → 配方原料 → 物品类型），由机器实际放置/敲击来验证，其他带有易变 NBT 的输入也能正常批量。
- 农夫乐事锅：图批次按输入缓冲的真实容量取批次；锅只能一次做一份时按一份顺序执行，不再出现“队列里有 2 份、worker 却一直不启动”的假执行。
- 污染大地之心：污染步骤接入图执行器，不再只创建节点不执行；完成污染后会把带污染 NBT 的大地之心发布回图材料并继续下一步，同时把大地之心放进玩家主背包空槽等待污染，超时或失败会明确中止并回收。
- 修复 `pattern_grid` 铁砧命名钩子在非合成终端上提前访问输入框的问题，`PatternGridIsolationTest` 恢复通过。

## 其他

- 计划树不再受 `recipeTreeMaxDepth`、`recipeTreeMaxNodes`、`recipeTreeMaxCandidates` 配置限制；仍保留内部安全上限，避免异常配方把客户端拖死。
- 配置同步包移除已删除的递归树字段；旧客户端连接新服务端时会使用默认值。
- 补充 Ars Nouveau 按配方判定执行机器类型、无状态即时机器合并、反向目标退化等规划兼容修复。
- 新增并行份额、燃料/催化剂/耐久工具展示、单变体分配、Embers 能力判断、污染大地之心、Aetherworks 兜底等回归测试。

## 升级提醒

- 多人游戏请同步更新客户端与服务端，使用相同版本的 RSI。
- 已有存档、机器绑定和配置继续兼容；删掉的并行配置项会被忽略，不需要手动迁移。
- 之前因为并行配置上限或“没有可用的已绑定机器”而绕路的存档，升级后可以直接使用默认并行。
- 发布文件名：`rs_integration-1.5.2.3.jar`。
