# RS Integration 1.5.2.1 更新公告

- 当前版本：1.5.2.1
- 公告整理：2026 年 10 月 27 日
- 适用环境：Minecraft 1.20.1 / Forge 47+
- 公告范围：从 1.5.2 正式公告基线开始，到当前 1.5.2.1 的全部玩家可见、机器兼容和接入方可见更新。

## 本版重点

- 新增 Integration API 1.1.x、Consumer API 1.0.x 和 Resonance Inventory API 1.0.x。
- 优化大型配方图的药水纯度匹配、可达性预计算、规划缓存和缺料诊断。
- 统一递归目标、概率产物、批量投料、机器等待、产物恢复和取消退款语义。
- 修复共振魔力池/魔源罐超过 `int` 上限后无法继续输入、Malum 催化剂重复返还、切割板递归制作和炼金锅批量执行等问题。
- 新增诅咒基座兼容，并统一项目许可证、整合包授权、内容创作者授权和贡献者 CLA。

## 公共 API

- Integration API 支持第三方声明物品配方、流体配方、机器描述符、标准输入输出、并发能力、支撑区域和特殊执行流程。
- 配方、机器和执行器按明确优先级解决归属；同优先级冲突会返回诊断，不再依赖注册顺序。
- Consumer API 支持配方目录查询、分页 inspection、纯规划、动态机器规划、单笔或批量下单、状态查询和取消。
- Consumer 订单使用稳定幂等 ID，并持久化预约、外部请求、实际产物和终态；服务端重启后不会重复执行已完成订单。
- Consumer 同时支持玩家背包、RS 和 BD 存储选择，并区分计划缺料、机器等待、输出恢复和输入不足。
- Resonance API 可打开短生命周期共振盘快照，按 `ANY_IDENTITY`、`EXACT_IDENTITY` 或 `PARTIAL_IDENTITY` 查询。
- Resonance API 要求先模拟再提取，实际提取按逻辑条目和完整 NBT 执行；内容变化会返回 `STALE_SNAPSHOT`，未分配插入会返回真实余额。
- 公共注册通过 Forge 事件总线发布；单个第三方适配器抛出异常时只隔离对应候选，不会中断后续配方、机器或执行器扫描。
- 第三方自定义执行支持瞬时快照、跨重启恢复、取消清理、操作幂等、预留材料校验、真实收取和完整处置确认。
- 公共 API 已提供独立 smoke mod、真实模组案例、边界测试和完整接入指南。标记为内部或未列入公共包的类型仍不属于兼容契约。

## 递归规划与结算

- 优化大型配方图的药水纯度匹配、可达性预计算、精确库存索引和规划缓存，减少重复扫描、无意义候选展开和高库存整合包中的规划超时。
- 递归诊断会区分真实缺料、无可用配方、循环依赖、递归种子、耐久不足、计划过大、机器等待、结果过期和上下文失效。
- 修复可自增配方、耐久工具和替代材料被错误当作循环或永久缺料的问题。
- 统一物品和流体的需求目标、生产目标、终端目标与中间产物交付语义，避免库存中已有中间产物时仍从原始材料重新规划。
- 规范化终端图的输出声明、生产目标和数量校验，动态身份产物会保留运行时 NBT，而不是只按显示模板结算。
- 概率产物只结算实际出现的物品或流体；未命中时保留真实进度，不会把最大概率结果当成保证产出。
- 批量机器按真实输入、燃料、容器、催化剂、单次投料能力和操作上限执行，支持一次输入材料后分成多次操作。
- 公共及外部机器适配器使用统一启动入口和准备阶段状态校验，避免机器已经忙碌、未准备完成或描述符变化后仍重复投料。
- 递归执行和跨 tick 调度共享预算、机器租约及捕获区租约，同一机器不会被重叠任务占用。
- 可恢复等待使用统一 `RETRY` 语义；能量、燃料或机器条件暂时不足时只显示一次不刷屏提示。
- 移除预览规划的隐式同步回退，避免服务端线程在主线程超时后偷偷重复执行完整规划。
- 执行阶段会重新读取库存快照并重抓缺料，避免预览后库存变化导致错误启动。
- 取消、失败或机器只完成部分操作时，只回收实际未使用的预留材料，不会重复退款或把已消费材料再次归还。
- 玩家背包、RS 或 BD 已满时，物品、流体和魔法资源产物会进入持久恢复队列；重新登录或腾出空间后可继续领取。
- 背包已满时，退款会先尝试进入可用存储网络；网络也不可用时才保留到离线退款队列。
- 优化恢复驱动结算的 tick 开销，同时保留对真实产物、剩余材料和取消状态的区分。

## 机器与模组兼容

- 新增神秘遗物：深邃诅咒的诅咒基座 API 兼容，支持邻接多方块结构、展示架材料、持久操作、失败回收和成品回写。
- 农夫乐事切割板缺少刀具时会递归准备刀具或剪刀，绑定状态和单次合成流程保持一致。
- Iron 炼金锅支持批量投料、一次输入材料、免费补水和 JEI 原生液体输出显示。
- 修复 Iron 炼金锅、Iron Furnaces 等外部机器一次输入材料后无法正确分发到多次操作的问题。
- 修复 Malum Spirit Crucible 耐久催化剂未完成一次操作时被复制或重复返还，并统一批量结算中的催化剂角色。
- 修复召唤祭坛实际已经开始或产出后仍被误报为失败的问题，并隔离第三方背包反射异常，避免拖垮整次结算。
- 修复 Wizards Reborn 秘蕴容器等待、机器路由和自定义批量准备状态，资源不足时会等待而不是错误消耗预留。
- 修复配方处理器同优先级冲突，确保 Embers、Malum、Wizards Reborn、原版机器和锻造处理器不会同时争用同一配方。
- 为 Ars Nouveau 标准物品/流体机器和 Iron 炼金锅补充公共 API 真实案例，验证有序材料、概率输出和自定义执行合同。
- 修复 JEI 15.20.0.112 下进入世界同步配方时的启动崩溃：`#` 前缀的 Spice of Life 搜索扩展不再 `@Shadow` JEI 内部 `allElements` 字段，改为只依赖 `IElementSearch#getAllIngredients()`，同时兼容 15.20.0.106、15.20.0.112、15.20.0.129 及更新版本。

## 魔法资源与共振容器

- 修复共振魔力池和魔源罐在单次输入超过原生 `int` 上限后只接收部分资源、无法继续输入或提前停止的问题。
- Botania 和 Ars Nouveau 的原生接口继续使用 `int`，但 RSI 侧使用 `long` 计算容量与余额并正确分段，最后一段不会产生零数量或负数量调用。
- 原生接口拒绝某一段写入时，未写入部分会完整返回给调用方，不会从容器中提前消失。
- `/rsi_debug` 和共振容器提示继续显示真实储量、容量、绑定网络和资源类型。

- 明确允许官方未修改版本用于私人或公开服务器、公开整合包和可变现的游戏视频或直播；禁止单独售卖模组或发布修改版。
- 新增贡献者许可协议和 PR 确认流程，项目只接受明确同意 CLA 的代码、文档或素材贡献。
- 发布 jar 附带第三方组件说明；`verifyReleaseJar` 会拒绝未审计的外部 class 和新增 jar-in-jar 依赖。
- README 补充 Modrinth、CurseForge 和 MC百科入口，公共 API 文档统一为一份接入指南。

- 第三方 API 接入方应在运行时检查各自 API 版本，并继续使用已发布的接口合同。
- 旧机器绑定、共振盘内容和离线退款会在首次加载时继续使用已有格式，不需要手动迁移。
- 发布文件名为 `rs_integration-1.5.2.1.jar`。
