# RS Integration 1.4.0 更新公告

**发布日期：** 2026 年 8 月 28 日


`1.4.0` 的核心变化，是将原本以 Refined Storage 为中心的功能逐步升级为后端中立的存储与合成体系，并正式接入 Beyond Dimensions。与此同时，递归合成的材料预留、并行调度、失败退款和机器兼容也经历了大规模重构。

## 重点摘要

- Refined Storage 改为可选依赖，核心存储层支持 RS 与 Beyond Dimensions 两类后端。
- Beyond Dimensions 接入递归合成、机器绑定、机器管理中心、自动进食、容器转移和多项补货功能。
- 新增 Beyond Dimensions 共振空间、共振磁盘和共振网络发生器。
- Farmer's Delight 砧板正式支持 JEI 入口、递归规划、批量切割、工具耐久和来源归还。
- Miner's Delight 铜锅加入独立机器识别和远程烹饪入口。
- Embers 炼金台改为由光束炮真实供能，炼金推断进度可跨重启保存。
- 重构递归合成的材料账本、预留、提交、退款和跨后端结算，减少吞料、复制、串库和错误回滚。
- 修复 Wizards Reborn 奥术迭代器批量合成中止，以及 Forbidden & Arcanus 炽炉绑定显示和燃料优先级问题。
- 修复仅使用 Beyond Dimensions 时，中键已经成功取出物品却仍提示加入 JEI 收藏的问题。

## 新增

### Beyond Dimensions 存储后端

- 新增 Beyond Dimensions 存储后端适配器，支持稳定网络引用、库存快照、物品身份、权限检查、模拟抽取、正式抽取、插入和失败结算。
- 递归配方计划可明确显示产物将进入 RS 网络或指定的 BD 网络，不再把所有存储目标笼统显示为 RS。
- 核心递归合成、机器投料、产物回收和退款会沿用下单时选定的后端，避免 RS 与 BD 同时存在时中途切换或串库。
- BD 终端新增机器管理中心入口，可查看绑定机器、搜索、滚动、收藏、远程打开、快速投入、快速收取和解绑。
- 配方计划和 JEI 机器入口会根据当前绑定后端分别发送 RS 或 BD 操作，不再让 BD 绑定误走 RS 网络包。
- 容器快速转移增加 Beyond Dimensions 模式，可将容器内容存入 BD 网络，并阻止把网络介质或已绑定升级存入其自身网络。
- 手持 BD 终端时会读取该终端的准确 `NetId`，不再从玩家可访问网络中随意选择第一个网络。
- BD 原生中键取出与 RSI 世界中键取出会合并为同一次成功操作；无论两个网络包的到达顺序如何，都不会重复取物或误触发 JEI 收藏。
- 在 BD 自身存储终端中使用一键存入时会拒绝把内容存回同一网络，并跳过绑定到目标网络的 `NetedItem`。
- 自动进食可在 BD 终端界面使用，食物和附加消耗从当前选定的存储后端读取。
- 附魔台青金石补货、村民交易补货、Apotheosis 重铸补货、铁砧记忆补货等路径改为使用通用存储网络。
- 世界中键取物、缺失材料提示、机器清理回收和一键存入等提示统一使用“存储网络”语义。
- 没有安装 RS 或 BD 时仍可查看只读配方树，并使用玩家物品栏进行基础规划；需要网络执行的操作会明确提示当前无可用后端。

### 玩家物品栏独立合成

- 玩家物品栏现在也是正式的合成材料端点，不再只是 RS 抽取失败后的临时兜底。
- 配方计划可将“玩家背包”选为最终产物去向；多步合成完成后只把最终目标送入背包，中间产物继续留在任务的虚拟库存中流转。
- 普通工作台步骤可直接聚合玩家物品栏中多个槽位的同类材料，先确认总量足够，再一次性抽取，避免抽到一半才发现不足。
- 玩家背包材料会进入与网络材料相同的预留视图，正在执行的任务会减少可用数量，取消或失败时按原槽位责任结算。
- 当最终产物无法完全放入玩家背包时，剩余物会继续尝试写入当前存储端；仍有余量时才安全交给玩家或掉落。
- 修复可装备、可进入饰品栏的产物在背包插入后又被完整交付一次，客户端短暂显示重复物品的问题。
- 未安装 RS 时，RS 专属注册、网络物品、侧栏、搜索历史和共振盘工厂不会加载；普通配方元数据、JEI 集成和玩家背包路径仍可初始化。
- 多方块机器依然需要对应机器结构、绑定与资源条件；“玩家背包产物”不会绕过机器校验或凭空提供网络能力。

### 共振网络发生器与 BD 共振空间

- 新增“共振网络发生器”，用于将独立共振空间绑定到 Beyond Dimensions 网络。
- 发生器首次使用时会绑定当前可访问的 BD 网络，并同时保存完整网络编号与共振空间标识。
- 发生器必须由玩家随身携带才会生效；失去对应网络访问权限后会停止提供共振能力。
- 同一网络的多个发生器会尝试合并到同一共振空间；空间容量不足时会保留独立空间并给出提示。
- BD 共振空间中的物品可参与被动效果、状态保存和资源查找，耐久、NBT 与运行时状态变化会写回对应空间。
- 每个 BD 共振空间包含 36 个逻辑槽位，总容量为 2304 件物品；不可堆叠物品仍按单件槽位规则保存。
- 共振空间的槽位、物品、拥有者、网络编号、能力掩码和内容修订号全部写入世界存档。
- 物品插入、抽取和被动效果修改均支持模拟模式；正式修改前会比较原槽位身份，防止旧界面覆盖已经变化的 NBT 物品。
- 同一玩家可同时解析多个有效共振视图，宝石数量、Lychee 催化能力和已解锁能力会合并计算。
- 打开共振背包界面时会暂停后台物品状态模拟，关闭后再恢复，避免界面快照与药水护符等持续变化物品互相覆盖。
- 新增 BD 共振磁盘物品、绑定/错误/迁移状态材质、机器中心标签和共振背包标签资源。
- 完善共振磁盘说明，明确支持药水护符、混合药水护符、烈焰术士法杖、石英花、幽灵之眼护符、九剑书、增益饰品和成组无限药水等能力。
- 细雪、原液、毒液、怨泉等桶装资源可继续作为递归合成资源使用。

### 共振被动能力跨后端

- 新增后端中立的共振物品桥，第三方兼容不再直接读取 RS 磁盘实现，而是查询玩家当前所有已授权共振空间。
- Enigmatic Addons 人造花可以从共振空间补充物品查询，贪婪指环会合并统计所有共振空间中的宝石数量。
- Enigmatic Legacy 的随身物品判定可以识别共振空间内容，依赖特定护符或物品存在的效果不再限定 RS 磁盘。
- Reliquary 烈焰术士法杖可从共振空间模拟检查并真实消耗燃料，提取数量会转化为对应充能值。
- Terra Equipment 自动药水会扫描所有共振空间中的成组效果药水，并继续遵守模组配置的最低数量。
- Wizard Terra Curios 增益物品会从所有共振空间应用效果，不再只检查第一张 RS 共振盘。
- Moonstone 与勇者章节的九剑书、拔刀剑数量和攻击力统计改为跨共振空间聚合。
- Lychee 的虚拟环境催化剂会合并共振视图中的能力状态，同时保持普通存储库存与共振催化空间的语义隔离。
- 共振物品发生耐久、药水状态或其他 NBT 变化时，会对原槽位执行比较后写回；槽位已被其他操作改变时拒绝覆盖。

### Farmer's Delight 砧板递归合成

- 新增砧板独立 JEI 合成按钮、绑定类型、配方识别和批量执行委托。
- 同时兼容 Farmer's Delight `1.2.8` 与 `1.3.3` 的砧板配方、显示结果和投放接口。
- 支持 `salvaging` 等目录型配方 ID，以及其他模组添加到砧板分类中的配方。
- 砧板输入按每次操作消耗，切割工具作为可复用工具处理，不会被错误加入普通递归材料图。
- 一个批次只预留一把工具，并根据真实操作次数计算耐久需求。
- 耐久损耗遵循原版耐久附魔随机判定；无法破坏的工具不会消耗耐久。
- 配方树会显示所选工具、工具来源、剩余耐久和耐久附魔等级，并提前阻止明显耐久不足的批次。
- 工具优先从所选后端对应的共振空间提取，缺少时回退到当前存储网络。
- 合成结束后会将工具归还原共振槽位或原存储端；归还失败时交给玩家，避免工具静默丢失。
- 支持随机副产物和不同版本的滚动结果结构，真实产物会统一收集并结算。

### Miner's Delight 铜锅

- 新增铜锅独立远程烹饪入口和机器类型，不再错误借用 Farmer's Delight 烹饪锅绑定。
- 支持其他模组放入对应 JEI 分类或目录下的铜锅配方。
- 铜锅的容器需求、产物数量和机器校验纳入递归计划。

### 动态 JEI 配方与烹饪兼容

- 新增 Cosmopolitan Tisane 动态配方解析器，可在逻辑服务端重建原本只由 JEI 生成的花草茶配方，使其可以进入递归计划和真实执行。
- JEI 配方 ID 规范化会继续拆除普通分页包装，但保留 `cosmopolitan:jei.tisane.*` 这类真实虚拟配方 ID，不再把它们截断成不存在的服务端配方。
- 新增机器分类隔离策略：共享 `CookingPotRecipe` 类的其他机器不会仅凭类名借用 Farmer's Delight 烹饪锅绑定。
- Farmer's Delight 烹饪锅、Miners' Delight 铜锅和砧板分别识别自己的 JEI 分类、配方目录和绑定类型。
- 其他模组放入 Farmer's Delight 烹饪、铜锅或砧板目录的附加配方，不会再因命名空间或子目录不同被误拒绝。
- 多份产出的烹饪配方会按真实成品数量规划碗、瓶等盛装容器，不再固定只取一个容器。
- 不同版本中“配方声明容器”和“产物返还容器”数量不一致时，会以实际需要为准替换计划材料，避免重复加入或少算容器。
- 配方输出数量、容器数量、显示槽和真实产物槽采用同一完成判定，减少机器已经完成却仍等待的情况。

### Embers 炼金与推断

- 炼金台不再由集成代码直接模拟点火，必须由 64 格内无遮挡、正确瞄准的光束炮真实发射。
- 光束炮至少需要 1000 Ember 才能启动炼金台；能量不足、未找到光束炮或发射后未启动都会显示独立原因。
- 炼金推断进度写入世界存档，不再依赖短期内存缓存或过期时间。
- 服务端重启、区块卸载或玩家稍后继续时，会从已完成尝试处恢复，不必重新枚举全部候选。
- 缺少炼金基底、Aspectus 或普通输入时会暂停推断，显示已完成尝试和剩余候选，并在补齐材料后继续。
- 上一轮炼金遗留的阻挡物品会优先回收到所选存储网络。

## 核心系统改进

### 后端中立的存储执行层

- Refined Storage 从强制依赖改为可选依赖；未安装 RS 时，公共初始化、网络注册和共振公共路径不会硬链接 RS 类型。
- 新增统一的 `CraftStorageEndpoint`，让递归合成和机器委托通过同一接口访问 RS、BD 或玩家物品栏。
- 存储会话明确记录后端、网络身份、权限和物品规范，任务执行期间不会重新猜测另一个网络。
- BD 的物品身份会规范化默认耐久标签和持久化空标签，避免显示相同的物品因后端 NBT 细节不同而无法匹配。
- 存储快照变化会参与计划有效性检查；数量变化、网络切换或绑定失效后，旧计划不会继续扣取新状态下的物品。
- RS 网络解析增加当前终端、网络物品、活动界面、玩家绑定和最近合法会话等分层路径，并修复旧网络引用导致“网络不可用”的问题。
- 未显式携带网络引用的一次性操作会优先解析玩家当前手持的 RS 或 BD 终端；Apotheosis、Goety、Forbidden & Arcanus、Wizards Reborn、Malum、Eidolon 和 Touhou Little Maid 等入口不再因发现顺序选错后端。
- BD 递归树库存缓存会在真实抽取和插入后更新，不再继续显示旧数量。
- 计划界面隐藏 `v1|` 等内部网络引用，只显示玩家可理解的后端名称和网络编号。

### 材料预留、提交与退款

- 重构材料账本，将计划预留、模拟抽取、正式提交、机器所有权、产物回收和失败退款拆分为明确阶段。
- 精确 NBT 材料、宽泛 Ingredient、可复用催化剂、每次操作替换物和跨后端材料分别记录，不再共用模糊数量。
- 模拟成功不再被视为已经扣料；只有正式抽取确认后才会推进对应账本状态。
- 部分抽取会立即回滚，不会把不足数量的中间材料留在网络中并让后续步骤继续执行。
- 退款只返还已经确认由任务拥有的物品；结果不确定时不会假装完整回滚，从而降低复制风险。
- 机器清理、玩家背包、RS、BD 和共振空间之间的回收都保留来源信息，优先归还原存储端。
- FTB Quests、背包升级和容器转移也接入统一结算逻辑，异常时不会把已移动物品既计为成功又再次退款。

### 递归图与批量调度

- 大量机器委托统一迁移到后端中立的材料端点，批量任务不再直接假定存在 RS `INetwork`。
- 并行合成组会继承子机器的私有账本调度能力，内部自主管理多阶段材料的机器可以安全进入递归图。
- 修复 Wizards Reborn 奥术迭代器单个合成正常、数量大于 1 时因 `delegate did not expose graph materials` 中止的问题。
- 并行工作者按自身账本预留和结算材料，失败的工作者不会影响已完成或仍排队的其他工作者。
- 可复用催化剂按机器并发能力预留；发生转化的催化剂按每次操作计算，保持不变的催化剂可由同一工作者复用。
- 通用烹饪包装器可以在选择具体绑定机器前报告并行能力，更多熔炉和同类机器能正确参与负载均衡。
- 增加“无可用机器”“全部机器忙碌”“任务分配失败”等明确错误，不再全部收敛为泛型合成失败。
- 合成链的最终产物会进入下单时选择的存储网络；网络满、玩家离线或回收失败时使用更严格的限流和失败处理。

## 功能与体验改进

### 机器绑定与管理中心

- 绑定流程可以识别玩家当前手持或装备的 RS/BD 终端，并在同时检测到多个终端时要求玩家明确选择。
- 新增独立机器绑定按键和 `Alt + 右键` 绑定提示，保留原有交互路径。
- 关闭 RS 侧栏现在只停止侧栏自身的同步和监听，不会同时关闭 RS 网络解析、递归合成或机器绑定。
- RS 侧栏在新配置中的默认值改为关闭；需要侧栏的玩家仍可在配置中手动启用。
- BD 机器中心使用独立网络包处理打开、投入、收取和解绑，避免调用 RS 专属界面返回逻辑。
- 机器绑定状态、收藏和终端切换后的网络归属同步更加及时。

### Sophisticated Backpacks 联动

- 次元拾取、次元磁铁、次元补货、次元喂食和 Restock 路径改为面向当前绑定的存储网络。
- 背包本地库存与远端网络之间的抽取、插入和异常恢复保留真实来源，避免失败后退回错误网络。
- 次元拾取会保留原始拾取上下文，兼容依赖拾取事件、所有者或世界来源判断的物品。
- 补货和喂食升级在远端存储不可用时会使用受控的本地背包路径，不会无条件访问旧 RS 引用。
- 增加自存储保护，禁止将背包或绑定升级送入它们自身所连接的网络。
- Feeding 会先从已解析会话快照选择食物，再执行精确抽取；进食被拒绝或仅消耗部分时，剩余食物返回同一存储引用。
- Refill 与 Restock 会保留目标槽位和后端引用，补货过程中网络失效时不会把已抽出的物品静默丢弃。
- Pickup 与 Magnet 会记录远端插入的真实接受量，只有后端确认接收的部分才从世界拾取结果中移除。
- Sophisticated Backpacks 遍历玩家所携带背包并运行升级时，会保留真实所属玩家上下文，使网络选择、权限检查和失败恢复不会丢失操作者身份。
- 升级提示统一说明本地能力与绑定网络后的附加能力，未绑定时仍保留对应的背包内操作。

### FTB Quests

- 任务提交改为原子结算：先确认任务实际接受数量，再结算网络或玩家物品栏中的材料。
- 任务拒绝、只接受部分数量、重复任务自动重置或提交过程中状态变化时，只退款未被接受的部分。
- 自动完成上下文与普通提交分离，避免一次任务进度更新被重复消费。
- 缺少材料时会区分“已加入 JEI 收藏”“原本就在收藏中”和“当前无法使用 JEI 收藏”。
- 提交过程支持玩家物品栏和选定存储后端，不再只依赖 RS。

### 自动进食、补货与容器操作

- 自动进食存储访问从 RS Grid 抽离，可在支持的 RS 或 BD 存储界面中使用。
- 食物、效果消耗和缺失材料均从当前选定后端计算，界面提示统一为存储网络。
- 附魔、村民交易、重铸、铁砧记忆和其他补货请求统一校验后端权限与实际库存。
- 一键存入、容器快速转移和中键取物支持通用存储后端，并增加网络自引用保护。
- 自动进食和补货在正式抽取时会校验全部返回分片的物品身份；异常分片与后端提供的恢复物品会退回原网络，无法退回的明确余量才会安全交给玩家或掉落。

### 配方计划、JEI 与错误提示

- 配方计划顶部会显示当前最终产物去向，并区分玩家背包、RS 网络和具体 BD 网络编号。
- 后端、库存数量、机器绑定或配方版本变化时会使旧计划失效，提交前重新校验，避免按过期预览扣料。
- 计划中的共振材料会显示真实来源，不再把普通存储、RS 共振盘和 BD 共振空间混成同一库存。
- JEI 的机器 GUI 按钮会按配方分类与当前绑定后端路由，避免同类配方打开错误机器或错误终端。
- 缺少材料时可通过计划界面中键加入 JEI 收藏；已经收藏的物品会显示不同提示，不会反复添加。
- 新增“配方材料无法解析”“合成账本状态错误”“材料提交失败”“链已中止”等分级错误。
- 机器验证失败会同时显示配方 ID、预期机器类型和实际类型，排查脚本配方与绑定冲突更直接。
- 异步链启动提示会根据产物去向分别说明“送入选定存储网络”或“送入玩家背包”。

## 机器兼容与修复

### Forbidden & Arcanus

- 修复 `forbidden_arcanus:clibano_center` 已绑定但 HUD 仍显示“可绑定”的问题。客户端会从外壳方块定位附近的真实主炉体，并与服务端保存的根坐标比较。

- 已有燃料时只补足当前任务缺少的数量，不再按总需求重复抽取。
- 自动选择燃料会跳过带容器返还、工具语义或危险 NBT 的燃料。
- 仪式启动器可从玩家背包或选定存储网络获取，缺少锻工锤时提供明确提示。

### Wizards Reborn

- 修复奥术迭代器批量合成无法暴露图材料契约而中止的问题。
- 多阶段法杖与奥术机器的材料提取、产物发布和退款改为使用任务自己的私有账本。

- 精魂坩埚中心输入保持可复用催化剂，不再随批次数量重复递归制作。
- 会发生转化的催化剂按每次操作预留，保持不变的催化剂只按工作者数量预留。
- 运行时配方和同时实现工作台接口的机器配方会优先交给 Malum 处理器。
- 修复配方刷新后聚焦输入、NBT 与库存数量未正确更新的问题。

### Iron Furnaces 与原版烹饪机器

- 白金砖高炉、烟熏炉、熔炉及更多熔炉的机器家族识别和并行能力得到统一。
- 烹饪包装器会在选中具体机器前验证配方族，避免绑定到错误炉型后才失败。
- 自动燃料选择、槽位容量、已有燃料补充和产物回收使用一致规则。
- Iron Furnaces 类型变化后的绑定同步支持 RS、BD 和混合安装环境。

### Botania

- 白雏菊转化保留真实捡取上下文和原始转化时间，不再因集成轮询缩短或重置处理时间。
- 可复用材料、世界方块产物和存储回收改用统一账本语义。

### Apprentice's Codex

- 精华烟熏炉会按真实的 8 个材料槽拆分物理批次，而不是把每个产物都当作一次完整机器启动。
- 催化剂消耗改为每 8 个材料使用 1 个；制作 1 至 8 个只需要 1 个催化剂，9 至 16 个需要 2 个。
- 批量投入会逐个调用原生材料接口；任意一步被拒绝时撤回已投入材料和催化剂，不留下半启动状态。
- 预期产物数量按本次实际投入的材料数计算，避免机器一次处理多个材料却只结算一个成品。
- 该机器使用独立的平坦执行规则，防止图调度按普通可复用催化剂错误放大或缩小需求。

### Farmer's Delight 与 Crock Pot

- Farmer's Delight 烹饪锅在启动前会回收所有旧输入、容器、显示物和产物，并将无法写回存储的余量交给玩家。
- 烹饪锅容器槽会使用同一账本中已经预留的真实容器，不再在材料提交后额外从网络抽取。
- 多份成品需要多个容器时，会把完整数量投入容器槽并按真实输出收取。
- Crock Pot 的食物等级填充物会从当前存储后端快照选择，配方树与执行阶段使用同一组类别匹配结果。
- Crock Pot 会把燃料需求纳入预览，并在执行时按当前后端补充；计划使用的燃料类型与实际填充保持一致。
- 取消任务时只回收本次自动加入且尚未消耗的燃料，不会抽走玩家原本放在锅里的燃料。
- 不同等级 Crock Pot 的输入槽、燃料槽和产物槽按实际机器容量计算，不再使用固定槽位假设。
- Farmer's Delight 煎锅、茶壶及其他烹饪委托继续支持世界产物捕获，并将结果写回选定后端。

### Touhou Little Maid、Distant Worlds 与 Goety

- Touhou Little Maid 祭坛会从选定后端统计并提取能量点物品，材料投入周围 8 个储物结构后再启动原生祭坛。

- Distant Worlds Lithum 祭坛会按 `distantWorldsFuelPriority` 从当前后端确定燃料，未列入优先级的燃料使用稳定 ID 顺序兜底。
- Lithum 祭坛记录任务开始前的燃料基线，只回收本次加入且仍未消耗的部分，不触碰机器原有库存。
- Goety 递归节点会继承整条合成链选定的后端，不再在祭坛阶段重新搜索 RS 并覆盖 BD。
- Goety 的材料可用性检查同时查看选定后端与祭坛基座，预览和执行使用一致结果。
- Goety 手动召唤、献祭和转化仪式会填好基座并把激活物交给玩家，但继续保留最终手动确认，避免自动召唤危险实体。

本次并非只给 BD 增加一层显示。以下委托的材料抽取、启动失败、取消、产物回收或账本注入至少有一项迁移到通用存储端点：

## 升级说明

- 模组版本升级为 `1.4.0`，发布文件为 `rs_integration-1.4.0.jar`。
- 网络协议从 `35` 升级到 `42`。客户端与服务端必须使用同一份 `1.4.0` JAR，旧版客户端无法连接新版服务端。
- 服务端配置结构仍为版本 `6`，无需删除已有配置。`vanillaFurnaceFuelPriority` 现在同时影响原版熔炉、更多熔炉和 Forbidden & Arcanus 炽炉。
- 新生成的通用配置默认关闭 RS 侧栏；已有配置会保留玩家或整合包作者当前设置。
- Refined Storage 现在是可选依赖。仅使用 Beyond Dimensions 时可不安装 RS，但 RS Grid 搜索历史、RS 侧栏和 RS 原生自动合成等界面专属功能仍需要 Refined Storage。
- BD 已接入核心存储和递归执行路径，但 RS 专属侧栏不会显示 BD 库存；BD 使用自己的终端与机器中心入口。
- 更新不会主动清除现有 RS 网络、机器绑定、机器收藏、自动进食偏好或共振磁盘内容。升级重要存档前仍建议保留世界备份。
