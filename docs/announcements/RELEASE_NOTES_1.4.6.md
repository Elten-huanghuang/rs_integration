# RS Integration 1.4.6 更新公告

本次更新新增 Biomancy 四类机器兼容，完善 RS 合成终端的虚拟工作站，并改进 RS 存储刷新、数据保存和 FTB Quests 任务检测。

## 血肉重铸兼容

- 新增消化体、生物炼金釜、分解体和生物锻造台的机器绑定、配方识别与批量执行支持，可参与 RSI 递归合成。
- 正确识别配方所需的材料数量与反应物，按照各类机器的实际槽位投料。
- 支持从存储网络补充营养燃料，优先使用营养膏；营养膏不足时可尝试递归合成，再寻找其他有效燃料。
- 分解体按保底产量进行规划，避免把随机产物当成必定获得的材料；执行后按实际产物结算。
- 补全四类机器的中文名称，并新增独立的 Biomancy 兼容开关。

## 虚拟工作站与机器管理中心

- 完善 RS 合成终端的工作站切换，支持在普通合成、切石机、锻造台和铁砧界面之间切换。
- 虚拟切石机和锻造台使用原版菜单逻辑，改进配方匹配、材料消耗和取出结果的行为。
- 修复工作站切换时的槽位同步错位，以及旧合成结果残留、可能重复领取产物的问题。
- 修复虚拟铁砧输入名称时可能出现的空名称崩溃。
- 改进工作站输入槽的 Shift 快捷转移，切石机只接收能够用于切石配方的材料。
- 调整机器收藏按钮的大小、位置和显示层级，避免与终端清空按钮重叠或遮挡物品提示。
- 新增独立配置，可控制远程打开机器界面是否需要绑定，以及虚拟工作站是否需要绑定对应的真实机器。默认远程机器界面需要绑定，虚拟工作站无需绑定。

## RS 存储优化

- 合并节点连接、解绑过程中重复触发的存储缓存重建，减少不必要的重复刷新。
- 存储缓存重建后及时刷新已打开的物品、流体和便携终端，减少库存列表显示旧状态的问题。
- 提高终端完整库存列表的传输上限，改善大量物品种类或 NBT 变体场景下的列表同步。
- 保存 RS 数据时先写入并校验临时文件，成功替换后才标记为已保存；保存失败时保留待保存状态，等待后续重试。
- 流体终端取出一桶流体前，先检查实际库存是否足够、流体是否能够装桶，避免无效操作提前扣减库存。
- 新增独立的 `config/rs_integration/storage.toml` 配置文件，上述优化默认开启，可分别调整；终端列表传输选项需要重启后生效。

## FTB Quests 与其他修复

- 优化连续解锁任务时的自动存储扫描，减少短时间内重复读取整个网络的开销。
- 修复任务检测队列可能长期滞留的问题，并及时清理过期请求。
- 修复任务进度更新时反复重建任务界面的问题，保留 JEI 任务条目的同步更新。
- 修复精妙背包从存储网络自动喂食时，可能误触玩家手持物品的问题。
