# RS Integration 1.4.2 更新公告

**发布日期：** 2026 年 9 月 8 日

## 新增

### 合成失败详细报告

- 任务中心现在可以打开只读的合成失败报告；合成失败时，聊天栏也会显示绿色可点击的报告入口。
- 新增本地客户端命令 `/rsi_failure_report <任务 UUID>`，可重新打开当前连接内保留的最近 8 条失败记录。
- 报告汇总目标、进度、失败分类、异常节点、配方、集成类型、机器位置、运行中操作和环境版本，并明确区分观测事实与排查建议。
- 详细 NBT 默认关闭；启用后仍受条目数、深度和总长度限制，避免超大标签拖慢界面或生成失控报告。
- 玩家可主动将报告导出为 UTF-8 文本，文件保存在当前游戏实例的 `rs_integration/reports/`。报告不会自动上传，导出前应检查其中的错误文本和坐标信息。

### JEI 作弊模式快捷键

- JEI 作弊模式下新增权限校验后的快捷操作：`Ctrl + 左键` 获取 1 个，`Ctrl + 右键` 获取该物品的最大堆叠，`Ctrl + Q` 丢出界面中显示的完整堆叠。
- 快捷键可以在“控制”界面重新绑定，并会避开搜索框等文本输入焦点。
- 丢出操作由服务端验证作弊模式和权限等级，要求权限等级 2；客户端不能通过伪造数据包绕过校验。
- `Ctrl + Q` 会保留 JEI 展示堆叠的 NBT，并将数量限制在物品自身的最大堆叠数内。

### JEI/EMI 配方按钮与材料状态

- JEI 和 EMI 的合成、机器操作按钮改用 RSI 自带 PNG 材质
- 新增服务端权威的材料可用性状态：灰色表示等待结果或暂不支持，红色表示当前直接材料不足，绿色表示至少能够执行一次。
- 材料状态由 JEI、EMI 和 Goety 共用同一套检查与缓存逻辑，减少不同界面之间结果不一致的问题。
- 颜色只表示当前存储端中的直接物品材料是否足够，不代表递归配方一定可合成，也不代表机器、电力、魔力或输出空间已经就绪。

### Crock Pot 鹦鹉喂食联动

- 新增鸟笼鹦鹉喂食的 RSI 配方和批处理支持，可通过配方界面远程准备材料、执行并回收结果。
- 仅存在于 JEI 的鸟笼喂食条目会在服务端按可验证数据重建，避免直接信任客户端配方。
- 鸟蛋结果可能随机变化；怪物肉也可能不会产出鸟蛋，执行与结算会按实际世界结果处理。

## 改进

### NBT 敏感配方与锻造升级链

- 带标签的配方输出现在可以满足下游只关心物品类型的需求，动态生成 NBT 的产物也能够继续参与递归规划。
- 库存中已有的带 NBT 物品可作为锻造升级链的起始材料，不再要求先重做一个无标签基础物品。
- 锻造规划和执行会保留不可破坏、耐久、附魔及其他动态状态，避免升级过程中错误剥离标签或用普通物品替换已修改工具。
- 加强候选配方、库存等价关系和执行输出之间的一致性校验，减少预览可行但执行阶段找不到正确 NBT 物品的情况。

### 规划性能与大任务调度

- 递归规划引入共享规划会话、库存与配方候选索引、查找缓存及配方图投影复用，减少同一次请求中的重复遍历。
- 可选配方目录的漂移检查移出服务器主线程，并使用代次校验丢弃过期结果，降低大型动态配方表对 Tick 的影响。
- 新增每次派发操作数、每 Tick 结算堆叠数和每 Tick 完成回调数等服务端上限；大型订单会分 Tick 推进，减少一次性结算阻塞终端。

### 同类机器并行执行

- 同类机器的大订单改为按有界窗口持续派发，例如 100 次操作可按 `32 + 32 + 32 + 4` 推进，不会只完成第一窗口。
- 并行组会累计各窗口的真实进度并继续补派任务；不同订单规模下都能正确收敛到请求数量。
- 前面的失效绑定不再遮蔽后续可用机器，所选存储端也会完整传递给每个工作者。
- 等待诊断改为采样记录尚未完成的工作者状态，不会因此新增强制超时或擅自取消仍可能完成的机器任务。

### 模组兼容与动态目录

- 适配 Beyond Dimensions `0.7.30` 的网络界面结构，RSI 侧边栏按钮可继续显示和响应。
- Beyond Dimensions 快照遇到单个无效物品身份时会隔离该条目，不再让整个网络快照失败。
- Iron's Spells 法术稀有度配置刷新后会正确使 RSI 缓存失效；单个损坏的法术或等级只跳过对应条目，不再丢弃全部有效法术配方。
- FTB Quests 最低兼容版本降至 `2001.4.10`，同时兼容该版本公开字段形式的任务 ID 与较新版本的访问接口。
- 在既有细雪桶虚拟合成支持上扩充 Lychee 物品浸泡配方的兼容范围；共振盘中的细雪桶仍作为不消耗的环境催化剂，批量执行不会按次数消耗或要求多个桶。

## 修复

### 批处理、种子配方与机器输出

- 修复受初始种子数量限制或会自我增殖的配方在大批量订单中错误失败：未提交的预留会缩小批次重试，前一批真实产物可作为后一批种子。
- 区分“材料预留失败”和“机器拒绝启动”，失败报告会保留更准确的阶段和原因。
- 修复相邻 Botania 魔力池并行工作时，一个工作者把邻池输入误认成自身输出的问题；现在要求匹配 Botania 的真实注魔输出标记，并统一捕获区域。
- 魔力池批处理会结合当前魔力选择批量规模；等待日志采用限频诊断，不改变原有等待语义。

### Eidolon 火盆仪式

- 修复 Eidolon 火盆仪式只处理核心试剂、没有正确准备基座祭品和焦点物品的问题；RSI 现在会按配方顺序预留材料并放入空闲的仪式提供器。
- 不变量物品仍作为必须提前搭建的持久结构条件，不会被当作一次性耗材从网络抽取；玩家已经放置的祭品也不会被 RSI 覆盖。
- 启动前会使用所选试剂验证完整仪式结构，并检查附近生物与玩家提供的生命值是否达到配方要求，避免扣除材料后才发现仪式无法运行。
- 结构不匹配、提交失败、启动失败或任务取消时，只清理由本次操作放置且身份仍匹配的祭品，降低吞料或误清玩家物品的风险。

### 次元磁铁与输出归属

- 修复放置型 Sophisticated Backpacks 中的次元磁铁没有在线玩家实体时丢失操作所有者、无法可靠使用绑定存储网络的问题。
- 次元磁铁绑定存储网络时会保存所有者 UUID 和名称；旧升级可通过背包访问记录恢复所有者，并在方块位置建立受控的离线玩家上下文。
- 磁铁产生的离线玩家不会被当作真实在线玩家重复统计外部物品进度，存储引用、权限和插入结果仍按实际所有者处理。
- Item Collectors 收集器和 Malum 虚空导管不会再夺走处于 RSI 捕获、结算区域内的在途产物。
- 改进世界输出、容器输出和取消恢复之间的所有权判断，降低重复回收、错误退款或产物被其他系统抢走的风险。
- 修复 Embers 炼金输出恢复与结果推断的边界问题，并补充光束炮点火状态的兼容保护。

### 数量溢出与异常方块绑定

- 修复大型外部存储库存进入合成可用量、材料账本和计划汇总时可能发生的整数溢出。后端快照继续保留 `long` 数量，必须进入 `int` 视图的值会饱和到 `Integer.MAX_VALUE`，不再绕回负数或产生虚假的缺料结果。
- 大数量的材料乘法、累计需求和可用量合并增加边界保护及明确诊断，超过当前规划器表达范围时不会继续使用已溢出的数值执行。
- 修复“自定义 GUI 模组列表”仅凭模组命名空间就允许绑定任意方块的问题。通用 GUI 回退现在只接受真正提供菜单的方块实体，装饰方块、普通方块和其他异常目标不会生成无效绑定。
- 已有专用机器注册不受通用菜单门槛影响，仍按各自的结构与机器校验规则绑定。

### 其他兼容修复

- 修复 Aetherworks 对输入槽和配方输入的错误处理，避免工具或材料被错误消费、恢复。
- 修复部分容器转移、共振磁盘能力和存储观察路径中的边界问题。

## 升级说明

- 模组版本升级为 `1.4.2`，发布文件为 `rs_integration-1.4.2.jar`。
- 网络协议从 `43` 升级到 `45`：协议 `44` 加入 JEI 完整堆叠丢出请求，协议 `45` 加入共享配方材料状态数据包并移除旧的 Goety 专用包 ID。客户端与服务端必须同时更新到 `1.4.2`。
- FTB Quests 的最低支持版本从 `2001.4.13` 调整为 `2001.4.10`。
- 服务端配置结构仍为版本 `6`，无需删除现有配置文件；新增限额会使用默认值写入或由配置系统补全。
- 本次更新不会主动清除存储内容、机器绑定、收藏、共振数据或合成任务进度。升级重要存档前仍建议备份世界和配置。
