# RS Integration 1.4.5.1 更新公告

这是一次以 Tetra/JEI 联动、递归合成稳定性和物品栏同步为重点的维护更新。下面列出本版本中实际加入或修复的主要内容。

## Tetra 与 JEI 联动

### 工作台材料筛选

- 打开 Tetra 加工台后，JEI 会根据当前目标物品、模块槽位和已选方案，自动筛选当前真正可用的材料。
- 只选择模块槽位、尚未选择具体方案时，会合并该槽位所有可用方案的材料；选中具体方案后会缩小到该方案允许的材料。
- JEI 原有搜索条件仍然有效；离开加工台、清空目标或切换工作台上下文后，会恢复原本的 JEI 物品列表。
- 在 Tetra 加工台中按住 Ctrl 并将鼠标悬停在 JEI 材料上，可以直接预览该材料应用到当前方案后的结果。
- 新增可选配置 `keepJeiMaterialPreview`，可以保留最近一次 JEI 材料悬停预览；目标、槽位、方案或工作台变化后会自动清除旧预览。

### 材料排序

- JEI 中新增 Tetra 材料排序面板，支持默认顺序、材料类型、硬度、密度、柔韧性、耐久、工具等级、工具效率、完整度增益、完整度消耗和魔法容量等字段。
- 支持同时启用主要和次要排序字段，并分别设置升序或降序。
- 新增排序面板的 JEI 避让区域和悬停提示，打开排序菜单时不会遮挡或误触 JEI 材料列表。

## JEI 从存储网络取出物品

- 新增 JEI 快捷键“从存储网络拉取一组”，默认使用鼠标中键。
- 在 JEI 物品上触发后，会从当前可用的 RS 或 BD 存储网络取出一组物品并放入玩家背包。
- 提取请求由服务端验证网络、权限、背包空间和实际库存；网络不足、无权限、背包已满、物品不存在或提取失败时会给出明确提示。
- 背包无法完全容纳取出的物品时，剩余物品会尝试退回存储网络，避免直接丢失。

## 递归合成与规划

### 配方选择和 RS 合成矩阵

- 纯递归规划在多个可行生产者之间会优先选择依赖层数更少的直接分解配方，减少不必要的工具或加工链，同时不改变正常可行性判断。
- 支持 RS Crafting Stations 等自定义合成矩阵：开始虚拟递归合成前，会先把矩阵中遗留的物品归还到网络。
- 合成矩阵无法完整归还时会取消本次递归合成并提示原因，不会继续使用不完整的库存状态。
- 修复玩家产物链中的 RS 矩阵规范化，避免矩阵物品被重复计算或错误当成可提取库存。
- 移除矩阵兼容流程中的调试日志，减少正常运行时的日志噪声。

### 规划超时和 FTB Quests 预览

- 为规划结果的最终校验增加独立超时边界；校验超时会停止请求并向客户端返回明确提示。
- 规划请求被取消时会正确结束进度状态，不会留下持续等待的进度 HUD。
- FTB Quests 批量提交预览现在会直接走任务规划器，不再启动普通递归规划 HUD 后一直等待不存在的结果。

## Confluence 与 Terra Curio 工作台

- 新增 Terra Curio 工作台配方类型、材料数量成分和 JEI 配方识别，兼容原有 Confluence 工作台路径。
- Terra Curio 工作台可以参与递归规划，并继续使用原有批量执行器处理实际工作台操作。
- 激活 Terra Curio 工作台的绑定目标，使绑定、查找和执行流程可以使用该工作台。
- F 键容器转移会识别并避开 Terra Curio 工作台，不会把工作台界面或玩家背包槽误判为普通机器输入槽。

## 玩家物品栏同步

- 虚拟合成、批量执行和机器产物进入玩家背包后，会立即同步实际变化的背包槽位。
- 即使玩家正在打开远程机器界面，也会同步当前快捷栏手持槽，避免客户端显示幽灵物品或旧数量。
- 在服务端菜单广播之后会再次补发延迟同步，修复远程界面旧快照覆盖新物品状态的问题。
- 物品栏同步逻辑会跳过 FakePlayer，并继续处理玩家区块未加载时的网络回收路径。

## 升级说明

- 版本号：`1.4.5.1`
- Minecraft：`1.20.1`
- 客户端和服务端必须使用同一个 RSI 版本。
- 本版本网络协议为 `54`；`1.4.5` 使用协议 `53`，旧版客户端不能直接连接本版本服务端。
- 现有 RS/BD 网络、机器绑定、收藏、共振数据、合成任务和 FTB 任务进度不会被主动清除。
- 现有配置文件无需删除，Forge 会自动补全新增的 Tetra JEI 预览配置。
- 升级前建议备份世界和配置，并删除实例中的旧版 RSI JAR，避免多个版本同时加载。
