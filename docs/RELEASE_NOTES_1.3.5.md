# RS Integration 1.3.5 更新公告

**发布日期：** 2026 年 8 月 22 日

本公告收录 `1.3.4` 更新公告整理提交 `fb0b937` 之后、截至 `49d3a63` 的全部 19 个提交。`1.3.4` 已公布的内容不再重复。

## 新增

### 附魔台青金石补货

- 在原版附魔台界面直接按空格，可从当前玩家可访问的 RS 网络补充青金石；按键会被补货操作独占，不会同时触发界面的其他空格键行为。
- 补货由服务端校验当前打开的确实是附魔台，并只操作青金石专用槽。已有青金石会补到槽位上限，通常为 64；槽内出现非青金石物品时会安全拒绝。
- 补货只会使用当前玩家解析到的 RS 网络，并检查 RS 提取权限。没有网络、没有权限或界面状态已经失效时，不会改动物品。
- 支持完整、部分和无需补充三种成功结果。RS 青金石不足时会显示本次实际补充数量和仍缺数量，而不是只提示失败。
- 结果会在附魔界面顶部显示 4.5 秒状态条，带青金石图标、缺少数量和成功/失败配色；完全补满与未补满使用不同提示音。
- 未能补满时会自动把青金石加入 JEI 书签，方便继续查找来源；没有网络和没有提取权限时也会执行这一回退。
- 请求与结果均通过受版本校验的网络包处理，服务端返回的数量被限制在合法槽位范围内，避免异常客户端构造无效结果。

### JEI 书签村民交易锁定

- JEI 书签现在可保护当前村民交易：只要当前交易列表中存在已收藏的产物，交易刷新模组的重刷操作就会被服务端阻止，避免刷掉想保留的交易。
- 匹配同时检查物品和 NBT，忽略堆叠数量。例如带不同附魔或数据的同类物品不会被错误视为同一条收藏。
- 支持 Retraining、Trade Cycling 和 TradeRefresh；三个模组共用同一套服务端锁定逻辑，可选模组缺失时不会产生硬依赖。
- 锁定状态按玩家隔离。每名玩家只使用自己的 JEI 书签判断，不会被其他玩家的收藏影响。
- 客户端书签变化会在 5 tick 防抖后发送完整快照，服务端建立最多 4096 条的轻量索引；高速连续刷新时不会反复复制或逐项扫描书签。
- 阻止刷新时会显示操作栏提示，同一玩家的重复提示限制为每秒一次，避免高速刷新模组刷屏。
- 服务端配置新增 `enableVillagerTradeLock`，默认开启；关闭后会跳过全部交易锁检查。

### 生存模式中键取物

- 生存模式下主手为空时，对着方块按选取方块键（默认中键），会先沿用原版逻辑寻找背包中的同类方块。
- 背包中没有时，会向当前 RS 网络请求 1 个对应方块；成功后显示实际取出物品和数量。
- RS 中也没有对应物品时，会自动将该方块加入 JEI 书签并给出提示；JEI 不可用时会明确说明无法收藏。
- 创造模式、主手已有物品、界面打开或未命中方块时不会接管原版按键；请求使用独立操作编号，避免异步结果对应到错误物品。

### 自动进食偏好持久化

- 自动进食模式和“指定食物”选择现在保存到玩家持久 NBT，退出服务器、服务端重启及玩家数据复制后仍会保留。
- 登录时会与食物黑名单、效果黑名单一起从服务端同步，客户端界面恢复真实的服务端状态，不再回到默认选项。
- 服务端会校验保存的物品 ID 是否仍然存在且确实可食用；模组移除、物品改名或存档中存在损坏值时会安全清除无效选择。
- 选择模式或指定食物发生变化时会立即同步给服务端；假玩家不会创建或覆盖玩家偏好。

### 存储后端基础设施

- 新增后端无关的存储访问层，统一描述存储后端、网络发现、默认网络选择、稳定网络引用、能力和可用状态。
- 新增标准化物品身份与库存快照。精确 NBT 变体、后端自定义身份、超大数量和同显示物品的不同后端记录可以保持独立，不再依赖可变 `ItemStack` 作为长期键值。
- 新增统一的查看、提取和插入权限结果，明确区分允许、拒绝、不可用和检查失败，避免“空库存”和“无法读取库存”被当成同一种情况。
- 存储操作结果现在区分模拟/执行、成功、部分成功、未找到、拒绝、无效响应、失败和结果不确定，并保留已经确认移动的真实物品。
- 新增结算账本，按预留组记录抽取、提交、回收和剩余责任。部分抽取、部分退款、恢复重试以及操作开始后抛出异常时，不会把未知状态伪装成成功回滚。
- Refined Storage 已实现首个后端适配器，包括网络定位、快照映射、权限、精确/Ingredient 抽取、插入、错误隔离和插入前追踪。
- 所有真实存储访问都要求在服务端线程执行；可选后端的加载、发现或可用性检查失败时只隔离该后端，不影响其他后端注册。
- 这项基础设施为后续兼容其他存储模组做准备。本版本玩家现有的 Refined Storage 使用方式、网络内容和界面入口保持不变。

## 改进

### 递归合成与配方规划

- 配方循环检查改为同时跟踪“配方 + 产物身份”和祖先产物，并把当前终端配方预先加入活动分支。终端配方不会再被错误选为制造自身输入的中间路线。
- 循环身份保留 NBT 区分，进入和退出分支使用结构化状态，不再依赖拼接字符串；异常退出也会释放活动标记。
- 配方树预览默认允许只使用玩家背包进行规划，即使当前没有无线终端或可用 RS 网络也能查看路线；实际下单仍执行原有网络校验。
- 新增 `requireRsNetworkForRecipeTree` 配置。需要保持旧限制的服务器可以要求打开配方树时必须存在可用 RS 网络。
- 后台纯规划的时间预算现在覆盖候选排序、可达性探测、部分树生成、成本计算和深层替代遍历，不再只约束主回溯循环。
- 达到时间限制但已确认最终缺少基础材料时，仍会打开有界的部分配方树，显示已找到步骤、最终缺料和超时警告，而不是直接丢弃全部规划结果。
- 部分树构建也会响应任务取消和截止时间；可达性缓存、失败状态缓存和最大步骤/候选限制共同约束大型模组包中的搜索成本。
- 非增益配方的宽标签输入若同时包含配方自身产物，会只排除该自消耗候选，保留标签中的其他合法材料；真正的自增益配方和催化剂语义不受影响。
- 这项修复覆盖木箱、变体材料等“上一批产物又被下一批当作输入但净产出为零”的情况，避免批量任务看似执行却没有增加目标数量。

### Goety 中间步骤前置条件

- 配方树会对每一个 Goety 中间仪式单独执行服务端前置检查，不再只检查最终点击的目标配方。
- 检查内容包括玩家研究解锁、仪式类型、手动确认要求、献祭实体、祭坛绑定、结构/合成类型匹配及远程祭坛加载状态。
- 缺少研究、祭坛绑定失效、结构不匹配或无法可靠完成检查时会标记为阻塞；需要手动确认、手动献祭或祭坛暂未加载时会显示对应警告。
- 警告随计划数据包同步到具体树节点。节点会显示警告/阻塞徽标和颜色，悬停时展示该步骤自己的原因，避免把中间仪式问题误显示在根节点上。
- 执行前仍会再次检查真实世界状态；预览中的远程未加载祭坛只做提示，不会被错误判定为结构已经损坏。

### 并行调度与材料结算

- Avaritia 压缩机、Crock Pot、Immortal's Delight 怨泉、Iron Furnaces、Youkai's Homecoming 料理台/水壶/摩卡壶等机器声明了明确的并发能力。
- 调度器会根据机器独占槽、委托直接产物和世界掉落实体等不同产物所有权选择是否并行，不再仅按模组 ID 粗略放行。
- 多台独立机器可以同时处理同一图节点；只有一台可用机器时仍会在该机器上顺序排队，不会为了并行而重复占用同一位置。
- 每个并行工作者的可复用催化剂预留改为独立记录。已启动机器归还催化剂后只结算自己的预留，尚未启动的排队工作者仍可正常退款。
- 工作者启动失败时会先统计已经捕获并确认的产物，只把尚未完成操作的输入标记为可恢复，避免完整退款导致已完成批次复制物品。
- 机器清理是否真正到达已加载的 BlockEntity 现在会被显式记录。只有确认物理材料已经从机器移除后，图预留才会退款，减少卸载机器、异常清理和取消竞态造成的吞料或复制。
- 长任务在节点推进、真实产物捕获和资源释放阶段会更新进度；并行组进入排空状态后会等待已启动工作者完成必要清理。

### 机器恢复与配方兼容

- 新增通用空闲机器物品撤离器，按槽位区分“返还真实物品”“丢弃虚拟显示物”和“保留机器资源”。只有确认机器空闲时才执行，工作中的机器不会被清空。
- Ars Nouveau 附魔装置会在新任务开始前回收中央槽已完成产物；灌注室只在确认现有内容是可安全回收的完成产物时取出，活动配方不会被打断。
- Ars Nouveau 附魔装置和灌注室会扫描并清空空闲基座上的旧物品，优先放回 RS，剩余物交还玩家，避免原生机器因占用基座拒绝下一次启动。
- Wizards Reborn 水晶注魔会在房间空闲时回收所有旧基座内容并同步 BlockEntity；无法可靠检查基座时保持原状，不冒险覆盖物品。
- Iron Furnaces 会在确认未烧炼时回收输入槽和产物槽，同时保留燃料；正在工作的熔炉返回可重试状态，不会被当成残留机器清空。
- Immortal's Delight 怨泉会回收处理槽、容器槽和产物槽，但保留机器燃料；活动中的怨泉同样不会执行撤离。
- Youkai's Homecoming 水壶会在处理进度为零时回收全部残留物；摩卡壶会清理完整的 7 槽库存，并在投入新容器前重新确认 RS 网络和实际抽取结果。
- Iron's Spells 'n Spellbooks 卷轴桌会在确定性自动配方启动前清理旧输入和产物，忽略纯客户端显示槽；无法完整清理时拒绝覆盖。
- Iron's Spells 奥术铁砧在专用 JEI 配方类未加载的服务端环境中，会根据法术等级和稀有度生成原生卷轴升级路线，专用服务器不再因缺少 JEI 客户端类而失去配方。
- Farmer's Delight 烹饪锅把碗等盛装容器作为每次操作的真实计划材料，并兼容不同版本的声明容器/原生剩余物接口；旧残留会在新任务前安全回收。
- Farmer's Delight 煎锅与原版营火统一解析 `CampfireCookingRecipe` 产物，兼容“产物留在槽内”和“产物以世界实体弹出”两类版本，不会同时结算槽内产物与捕获实体。
- Farmer's Delight 煎锅绑定不再被第三方 `campfire_cooking/...` 配方 ID 错误缩窄为原版营火；已绑定煎锅可正确执行其他模组添加的营火配方。
- Youkai's Homecoming 烹饪锅会在空闲但残留上次半成品时先撤离物品，避免调度器不断重试同一台无法启动的机器。
- Malum 灵魂坩埚与原版机器的产物捕获改为以实际操作捕获结果为准，减少“已产生世界物品又退款输入”造成的重复结算。
- Forbidden Arcanus 锻造台升级会记录初始等级、所需等级和目标等级，直接检查世界中的锻造台方块是否达到目标；升级方块状态不再被当作必须捕获的物品产物。

### 界面、JEI 与操作体验

- 机器集成中心恢复并明确显示快捷操作：左上角星标管理机器快捷栏，`Ctrl` + 左键解除绑定；达到收藏数量上限时显示具体上限提示。
- 配方计划的下单按钮现在直接显示“提交后会清空机器槽位，原有物品优先回收到 RS”的提示，不再只在特定悬停分支中出现。
- 附近绑定操作直接修改玩家物品 NBT 后，会同时同步玩家背包和当前打开菜单，绑定物品不再要等到下一次普通点击才刷新。
- JEI 框选的 `Alt` 按模组筛选现在同时识别 JEI 右侧物品列表、JEI 书签区、玩家背包、快捷栏及当前容器槽位。
- JEI 配方按钮兼容旧版 `recipeLayout` 与新版 `getRecipeLayout` 包装器，以及旧版 `updateRecipeButtonPositions` 与新版 `updateLayout` 布局回调。
- 远程机器按钮会从当前 JEI 配方布局读取真实传输按钮区域并重新避让已占用区域，升级 JEI 后不再因内部类名变化而消失、错位或启动崩溃。
- 容器快速转移模式会忽略原版 `F3` + `G` 区块边界快捷键，按下调试组合键时不再同时切换 RSI 转移模式。
- Apotheosis 重铸补货的空格键现在会取消界面原事件，并以 250 ms 间隔抑制系统按键重复，避免一次按键发出多个补货请求。
- 重铸补货同步刻印材料槽时会跳过一次 Apotheosis 客户端伪刷新，防止只因客户端数量更新就重新随机生成并不存在的重铸选项；服务端响应后会清除抑制状态，不影响下一次真实交互。
- 世界中键取物、机器快捷栏上限和当前服务器搜索历史“清空全部”等操作补充了准确提示文本。
- 磁铁、拾取、补货和自动进食升级补充 32×32 与 128×128 两套图标资源，兼顾物品列表和较大界面显示。

### FTB Quests 与服务端性能

- FTB Quests 的 JEI 任务配方更新增加防抖，不会在短时间内为每次客户端任务同步都重复刷新 JEI。
- 比较内容只包含 JEI 实际可见的需求、剩余数量和 NBT，忽略候选顺序、无关堆叠数量及超过显示上限的进度。
- 内容没有实际变化时不会重复注册配方或输出日志；任务要求确实变化时仍会及时刷新。
- 配方索引预热、后台计划取消和有界搜索路径补充契约检查，减少重载配方或玩家快速切换预览时遗留无用任务。

## 修复

### 合成、退款与任务收尾

- 修复终端配方通过自己的产物反向制造输入时形成递归环，导致计划停滞、候选反复回滚或达到超时的问题。
- 修复宽标签输入错误消耗上一批目标产物、使批量合成没有净产出的问题；精确自增益配方仍会保留必要的种子物品。
- 修复机器拒绝启动后，已从机器清出的未完成操作材料没有重新变为可退款状态的问题；已捕获产物对应的操作不会重复退款。
- 修复图执行取消时可复用材料已经从物理机器回收，却仍保留在共享预留账本中，导致退款遗漏或后续任务认为材料被占用的问题。
- 修复卸载/消失机器与已加载但清理失败机器使用同一种退款判断的问题，避免没有真正取回物品时直接虚拟退款。
- 修复烹饪锅使用 `ItemStack#getBurnTime(null)` 无法识别部分模组燃料的问题，统一改用 Forge 燃烧时间钩子；自动选燃料、优先级选择和槽位校验采用同一规则。
- 修复 Crock Pot 启动失败后的输入恢复和并行组收尾，已经完成的捕获产物会保留，未完成批次才会回收材料。
- 修复 Farmer's Delight 烹饪锅重复追加盛装容器、没有把容器计入每次操作需求或旧槽位阻塞下一单的问题。
- 修复煎锅/营火在不同版本中产物位置不同，导致提前完成、等待不存在的世界掉落或产物与退款同时发生的问题。
- 修复服务端无法加载 Iron's Spells JEI 奥术铁砧配方类时，卷轴升级递归路线完全缺失的问题。

### 机器与多人绑定

- 修复 Ars Nouveau 中央槽、基座或灌注室遗留完成品后下一次自动任务被原生机器拒绝的问题。
- 修复 Wizards Reborn 水晶基座遗留物不会在空闲状态回收，后续任务可能覆盖或一直等待的问题。
- 修复 Iron Furnaces、怨泉、水壶、摩卡壶和卷轴桌只有在部分失败路径中才清理库存，正常完成后残留物可能长期占槽的问题。
- 修复多个玩家绑定同一机器坐标时，共享内存索引只按位置和类型保存，后绑定玩家可能覆盖、读取或解除其他玩家绑定的问题。
- 机器绑定现在按“维度 + 坐标 + 玩家 UUID + 绑定类型”隔离；同一玩家的 RS、共振磁盘等不同绑定槽也互不覆盖。
- Goety 的 RS 可用性检查、绑定物品抽取和 NBT 重建均携带当前玩家身份，不会回退到其他玩家在同一祭坛上的网络。
- 世界方块被真正移除时仍会清理该坐标的全部玩家缓存；普通解绑只移除发起玩家自己的对应绑定。
