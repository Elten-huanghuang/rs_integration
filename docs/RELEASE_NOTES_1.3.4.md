# RS Integration 1.3.4 更新公告

**发布日期：** 2026 年 8 月 17 日

本版本包含 `1.3.3` 发布提交 `8e38369` 之后，到 `1.3.4` 发布为止的全部改动（`f0f2f9c` 至 `13a6751`）。`1.3.3` 已公布的内容不在这里重复。重点是递归规划性能、动态产物结算、KubeJS 材料语义、批量机器调度，以及新模组和新旧版本兼容。

## 递归合成与材料安全

1. 修复运行时 NBT 产物的图结算。Goety、Wizards Reborn、锻造和其他动态配方会根据真实产物身份发布结果，避免成品已经进入 RS 或玩家背包却提示 `output shortage`。
2. 完善节点产物累积与输出跟踪，防止动态产物、多个同类输出和运行时变体在图节点与执行步骤之间丢失对应关系。
3. 修复 FTB Quests 在团队数据锁定或任务进度拒绝时的结算，未被任务接受的物品会正确退款，不再被提交流程吞掉。
4. 完善并行操作的材料所有权、准备状态和资源清理。取消、超时、延迟启动和委托拒绝时，不会重复退款或遗留已预留材料。
5. Ars Nouveau 附魔装置延迟启动时会等待原生机器真正接受配方，重试过程不会重复扣料或重复退款。
6. 合成链的无进展计时器会在节点完成、机器状态推进或实际产物发布时重置，长耗时机器不会因为一直沿用初始计时而随机超时。

## 配方规划与性能

1. 重构纯需求树检查，将普通缺料、无法投影的特殊依赖和节点上限分别记录，普通缺料不再无条件回退到主线程 typed 解析器。
2. 大型标签只进行有界候选探测，找到可表达的普通路线后停止扫描所有同产物压缩、解压和容器变体。
3. 剪除没有库存种子的反向解压路线、压缩/解压闭环和无收益材料变体转换，同时保留有库存支撑、精确产物或数量确有增长的有效路线。
4. 修复 Prefab 高级农场等配方在大量木材种类下反复遍历木材、木板、木箱和砖块压缩链的问题。
5. 材料不足时仍会生成可读的部分配方树，展示已经确定的压缩链和最终缺少的基础材料，不再只显示笼统超时。
6. 强制选择的替代配方会贯穿后续递归解析，避免用户选定路线后又被库存中的另一种物品或默认配方替换。
7. 配方计划缓存增加状态重验，只有库存、网络、机器绑定和配方版本仍匹配时才复用旧计划。
8. 默认规划预算调整为：后台纯规划 `1500 ms`、主线程 typed 预览 `500 ms`、执行解析 `2000 ms`。简单配方仍会立即返回，不会固定等待完整预算。

## KubeJS、催化剂与批量语义

1. 新增 KubeJS 工作台配方语义识别，区分普通消耗品、返还容器、可复用催化剂、复制模板和运行时输出。
2. 批量选择 64 次时，可复用催化剂只按并发实际占用量计算，不会错误要求递归制作 64 个催化剂。
3. 防止催化剂、模板和其他剩余物在预留、执行、取消及副产物回收阶段被重复计数或错误吞掉。
4. 泛型批量委托会按机器容量和物理批次大小拆分任务，熔炉及其他可整组处理的机器不会无故退化成逐个执行。
5. KubeJS 工作台配方带有阶段限制时，预览和执行都会检查玩家是否已解锁对应阶段；未解锁配方不会进入递归候选，也不会先扣材料再失败。

## Botania 与 MythicBotany

1. 新增 MythicBotany Mana Infuser（精灵凝聚板）自动合成和中文名称，原生配方与 KubeJS 自定义配方均可进入递归合成链。
2. Mana Infuser 会验证多方块结构、材料、魔力和产物，并使用独立捕获区完成批量投入、结果收集、取消和退款。
3. 新增 Improved Botania Pools 兼容，可直接绑定 Alfheim、Asgard、Muspelheim 和 Nilfheim 四种扩展魔力池，并复用 Botania 灌注、催化器、批处理及负载均衡逻辑。
4. 修复 Botania 配方在 JEI 和机器绑定中的分类，Mana Pool、催化器及 KubeJS 配方会路由到实际可执行的机器。
5. 白雏菊方块转换会向图调度报告结构的实际并发容量，批量任务不再退化为逐个执行。

## Goety

1. 支持灵魂图腾及其派生图腾作为可复用能量催化剂，批量合成按灵魂能量消耗展示需求，不再把每次合成都展开成一只新图腾。
2. 图腾剩余能量和 NBT 会在合成后正确返还，根之图腾等具有同类灵魂能量语义的物品也可复用。
3. 祭坛前置条件改为候选机器独立验证。绑定多个祭坛时，一台条件不足不会阻止其他满足条件的祭坛执行。
4. 支持动态附魔仪式和运行时结果验证，Goety 成品已经进入目标库存时不会再误报缺失。
5. 修复图执行与祭坛委托间的结果发布、回收和候选切换问题。
6. 新增狰狞注入器与 Goety Awaken 魂咒融注器兼容。三台机器共享诅咒注入配方入口，但会按原生能力筛选普通/Grim 配方；增强机器使用 64 个独立配方槽并行工作，魂咒融注器的装备与图腾修复槽不会被占用或清理。

## Iron's Spells 与 Ars Nouveau

1. Iron's Spell Books 卷轴撰写台不再依赖脆弱的远程菜单状态判断产物，而是直接按机器输出和目标卷轴数据验证成功。
2. Ars Nouveau 动态配方分类更加严格，避免把不支持自动执行的运行时配方错误加入普通递归图。
3. 延迟获得魔源或等待原生机器状态变化的配方可安全重试，不会发生双重抽取。
4. 新增 Ars Nouveau 抄写台魔符递归合成，支持 `ars_nouveau:glyph` 原生及同类型数据包配方；抄写台任意一半均可绑定，并统一归一到同一逻辑机器。
5. 抄写台启动前检查玩家经验，完成时自动捕获魔符产物；取消或启动失败时材料由 RS 账本返还，已扣经验单独返还，避免重复退款或吞料。

## Immortaler's Delight 与共振磁盘

1. 同时兼容 Immortaler's Delight 旧版和新版 Enchantal Cooler（怨泉）的类名、字段和配方结构。
2. 新版怨泉的燃料、产物、机器绑定和 JEI 入口可以正常递归规划与执行。
3. 共振磁盘支持 `immortalers_delight:hot_spring_bucket` 怨泉桶及 `hot_spring` 怨泉水的资源语义，同时保留旧版本液体和旧配方兼容。
4. Lychee 虚拟配方和共振磁盘同步会保留相关桶、流体及 NBT 状态。

## Youkai's Homecoming 与 Gensokyo Delight

1. 兼容 Gensokyo Delight 0.5.0 发酵罐的 `inputFluid` / `outputFluid` 配方结构，同时保留 Youkai's Homecoming 旧版水量字段和容器行为。
2. `white_wine`、`red_wine` 等纯液体发酵会把对应装液容器显示为递归材料，不再在配方树中显示“空气”或“无可解析的材料”。
3. `champagne`、`burgundy`、`van_allen` 等混合发酵会同时规划固体材料与输入葡萄汁；执行时液体进入流体槽，容器不会被误塞入物品槽。
4. 发酵完成后空容器作为副产物回收；取消或失败时由机器或共享材料账本择一返还原装液容器，避免吞液体或双倍退款。

## 机器路由与远程 GUI

1. Avaritia 各级工作台会按照实际工作台类型、槽位数量和绑定机器执行，不再被相近配方 ID 路由到错误机器。
2. Botania、Avaritia 及其他机器特定配方增加明确绑定规则，降低只依赖配方 ID 或类名前缀造成的误判。
3. Wizards Reborn 奥术迭代器会在分派材料前检查当前结构的基座数量；基座不足的候选机器会被拒绝，并显示已有/所需数量，而不是投入材料后才失败。
4. Iron Furnaces 工厂/彩虹熔炉、原版烧炼包装器和其他支持物理批处理的机器会把真实容量传给图调度，递归合成不会再固定按一次一个执行。
5. 泛型委托新增明确的图执行能力契约；不支持图执行的机器会在提取材料前回退或拒绝，避免启动后才出现 `delegate rejected graph dispatch`。
6. 新增 Placebo 系机器远程菜单快照。远程打开依赖服务端 BlockEntity/Menu 状态的机器时，会同步必要数据后构造界面。
7. 关闭远程 GUI、机器消失、并行任务切换或合成链中止时，会释放菜单上下文、捕获区和准备资源。
8. 修复熔炉类、Iron Furnaces、Embers 炼金台和若干批量机器在前一轮结束后残留准备状态或资源占用，导致下一轮启动失败的问题。

## RS 搜索与机器管理

1. 新增 RS 搜索历史浮层，保存最近搜索词，支持按搜索模式恢复、收藏、取消收藏、单条删除和清空。
2. 搜索历史会持久化到客户端文件，并对数量、文本长度和损坏数据进行限制与恢复。
3. 新增机器收藏功能。机器管理中心和侧边栏可以收藏常用机器，收藏状态按玩家保存并同步。
4. 机器收藏、解绑和机器失效后的列表状态会及时刷新，避免显示已经不存在或已经取消绑定的机器。
5. 更新网络数据包和客户端处理器，为搜索历史、机器收藏和远程菜单快照提供同步支持。

## 稳定性与测试

1. 增加规划状态校验，异步结果返回后会重新检查玩家、配方版本、库存、RS 网络和机器绑定，过期计划不会直接执行。
2. 扩充 Prefab 木材链、砖块压缩链、宽标签、强制候选、动态 NBT、Goety 图腾、Improved Botania Pools 绑定、MythicBotany、Immortaler's Delight、远程菜单和退款路径测试。
3. 可选模组缺失或版本字段变化时继续使用反射能力探测和安全降级，避免共享代码硬链接可选模组类型。
4. 改进失败原因和日志分类，普通缺料、规划超时、节点上限、候选机器不满足和实际产物缺失会分别报告。

## 升级说明

- 模组版本升级为 `1.3.4`，发布文件为 `rs_integration-1.3.4.jar`。
- 网络协议从 `31` 升级到 `32`。客户端与服务端必须使用同一份 `1.3.4` JAR，旧版本会在连接阶段被拒绝。
- 服务端配置结构升级到版本 `6`。启动时会把旧默认的纯规划预算 `500 ms` 迁移为 `1500 ms`、typed 预览预算 `400 ms` 迁移为 `500 ms`，并把旧默认的计划缓存寿命 `500 ms` 迁移为 `30000 ms`；所有非默认自定义值都会保留。
- 执行解析预算仍为 `2000 ms`。无需删除配置文件或世界数据。
- 更新不会清除 RS 网络内容、共振磁盘、机器绑定、机器收藏或已有炼金编码缓存。
